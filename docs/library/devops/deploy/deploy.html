# Deploy

This skill covers three distinct deployment targets. Select the section that matches the current project.

## Azure IaC Deployment

1. Dispatch the preflight sub-agent using the complete template from subagent-preflight.md. Do not summarize or rewrite the template.
2. Read prepare-plan.json and scaffold-manifest.json from the session directory. Check validationResult.
3. Run preflight checks: auth, mandatory what-if preview, RBAC, and resource group validation per deploy-checklist.md.
4. Present cost and resource summary for user approval.
5. Write deploy-result.json skeleton with status in-progress before any az command.
6. Generate portal link and auto-open in browser. Auto-generate all @secure() parameters; never ask user for passwords. On retry, reuse secrets from deploy-secrets.env or Key Vault.
7. Execute az deployment sub create.
8. Deploy application code for every service in prepare-plan.json.services[].
9. Health-check each endpoint (max 3 iterations). For multi-service apps, inspect response body for error patterns. For every App Service/Functions app, disable SCM basic publishing credentials and verify.
10. Return control to the azure-app-onboard orchestrator.

## Power Platform Code App Deployment

1. Check memory-bank.md in the project root for project name and environment.
2. Run npm run build. If build fails with TS6133, remove unused import and retry. For other TypeScript errors, report and stop. Verify dist/ exists with index.html.
3. Ask user for explicit confirmation before deploying.
4. Resolve the CLI binary per cli-binary.md. Run pa app push (or power-apps push on power-apps-only projects).
5. Capture app URL from output. If deploy fails, report error and stop. For auth errors, run pa auth logout and retry. For environment mismatch, update environmentId in power.config.json.
6. Update memory-bank.md with last deployed timestamp and app URL.

## Quarto Slides to GitHub Pages

1. Run ./scripts/sync_to_docs.sh with the lecture argument if provided, or without argument to sync all lectures.
2. Verify HTML files exist in docs/slides/.
3. Verify _files/ directories were copied for RevealJS assets.
4. Verify docs/Figures/ was synced from Figures/.
5. If applicable, grep rendered HTML for interactive widget count and confirm it matches expected.
6. If applicable, check that all referenced TikZ SVG files exist in docs/Figures/LectureN/.
7. Open the rendered HTML in a browser for visual verification.
8. Report results to the user.
