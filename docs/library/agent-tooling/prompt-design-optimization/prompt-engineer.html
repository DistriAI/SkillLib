# Prompt Engineer

This skill supports three modes of prompt engineering: full lifecycle development, advanced technique application, and prompt transformation via frameworks.

## 1. Lifecycle Engineering (Design & Test)
Use this mode when building new prompts or refactoring existing ones for production.

1. **Understand requirements**: Define task, success criteria, and edge cases.
2. **Design initial prompt**: Choose a pattern (zero-shot, few-shot, CoT).
3. **Test and evaluate**: Run diverse test cases. If accuracy < 80%, identify failure patterns before iterating.
4. **Iterate and optimize**: Make one change at a time to refine reliability and token efficiency.
5. **Document and deploy**: Version the prompt and monitor production performance.

## 2. Advanced Techniques & Model Optimization
Use this mode when optimizing for specific models or advanced reasoning.

- **Reasoning**: Apply Chain-of-Thought, Tree-of-Thoughts, or Self-Consistency for complex tasks.
- **Safety**: Use Constitutional AI principles and critique-revise patterns for alignment.
- **Model-Specific**: 
  - *OpenAI*: Optimize function calling and JSON mode.
  - *Anthropic*: Use XML tags and tool use optimization.
  - *Open Source*: Adjust for special tokens and context limits.
- **Output Constraint**: When providing a final prompt in this mode, ALWAYS display the complete prompt text in a single, clearly marked, copy-pasteable block.

## 3. Framework-Based Transformation
Use this mode to transform vague user prompts into structured ones.

1. **Analyze Intent**: Detect task type, complexity, and clarity.
2. **Clarify (Conditional)**: Ask max 3 questions only if task type or scope is critically ambiguous. Otherwise, proceed with available context.
3. **Select Framework**: Map the task to a framework:
   - *Role-based*: RTF (Role-Task-Format)
   - *Reasoning*: Chain of Thought
   - *Complex Projects*: RISEN or RODES
   - *Summarization*: Chain of Density
   - *Communication*: RACE
   - *Goal-setting*: CLEAR or GROW
4. **Transform**: Rewrite the prompt using the selected framework(s). Blend 2-3 frameworks if the task spans multiple types.

## Constraints
- **MUST**: Test prompts with diverse inputs and measure quantitative metrics.
- **MUST NOT**: Deploy without evaluation or make multiple changes simultaneously when debugging.
- **MUST NOT**: Hardcode sensitive data in prompts.
