The three copies describe three different procedures for improving a skill. The first (trailofbits) is a wrapper that resolves a path and launches a background workflow (improve.js) with a reviewer agent, ledger, and scope guard. The second (sickn33) is a manual loop where the agent directly calls the skill-reviewer, categorizes issues, fixes them, and uses a specific completion marker. The third (brycewang-stanford) is a plan-executor that reads a pre-generated improvement-plan file, parses it, resolves conflicts, and applies changes with backups. Because they rely on different inputs (workflow vs. direct agent call vs. plan file) and have distinct mechanisms (background loop vs. interactive loop vs. batch execution), crowning one would hide the other valid approaches.

# Skill Improver

This skill provides three methods for improving a Claude Code skill. Choose the method that matches your available tools and inputs.

## Method 1: Autonomous Workflow Loop (Recommended if available)

Use this method if the `code-improver` plugin and `plugin-dev` plugin are installed.

1. **Resolve Target**: Identify the skill path from arguments or conversation.
2. **Locate Workflow**: Find `workflows/improve.js` in the plugin root.
3. **Launch Workflow**: Use the Workflow tool with `scriptPath` and args including `target`, `reviewer` (plugin-dev:skill-reviewer), and `maxRounds`.
4. **Monitor**: Wait for the workflow to complete. It handles the review-fix loop, ledger, and scope guards automatically.
5. **Report**: Relay the structured result (converged, capped, or escalated).

## Method 2: Interactive Review-Fix Loop

Use this method if you have access to the `plugin-dev:skill-reviewer` agent but not the workflow tool.

1. **Review**: Call `plugin-dev:skill-reviewer` on the target skill.
2. **Categorize**: Parse issues into Critical, Major, and Minor.
3. **Fix**: Address all Critical and Major issues.
4. **Evaluate Minors**: Assess minor issues for validity; fix only those that provide clear value.
5. **Verify**: Re-run the reviewer to confirm fixes.
6. **Complete**: When all Critical/Major issues are resolved and Minors are addressed or dismissed, output the marker: `<skill-improvement-complete>`.

## Method 3: Plan Execution

Use this method if you have a pre-generated `improvement-plan-{name}.md` file.

1. **Load Plan**: Read the improvement plan file.
2. **Parse**: Extract changes grouped by file and priority (High/Medium/Low).
3. **Resolve Conflicts**: Apply priority rules to conflicting changes.
4. **Backup**: Create a backup of the skill directory.
5. **Execute**: Apply changes in priority order using Edit/Write tools.
6. **Verify**: Check YAML syntax and file integrity.
7. **Report**: Generate an update report documenting changes and verification results.

## Common Guidelines

- **Severity Handling**: Always fix Critical and Major issues. Evaluate Minor issues for cost-benefit.
- **Validation**: Ensure the skill remains valid (YAML syntax, file paths) after changes.
- **Scope**: Only modify files within the skill's directory unless explicitly instructed otherwise.
