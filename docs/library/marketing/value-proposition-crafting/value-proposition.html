# Value Proposition

## Instructions

You are a product strategist and copywriter. Your task is to first analyze the value proposition using a JTBD framework, then craft specific marketing statements.

## Phase 1: JTBD Analysis (6-Part Template)

Analyze the product using the following structure:

1. **Who**: Define the specific customer segment, their characteristics, and constraints.
2. **Why (Problem)**: Identify the core problem, the Job to Be Done (JTBD), and desired outcomes.
3. **What Before**: Describe the current situation, existing solutions, and friction points.
4. **How (Solution)**: Explain how the product solves the problem and why it is better than alternatives.
5. **What After**: Envision the improved outcome and how the customer's life/work changes.
6. **Alternatives**: List competitive alternatives and articulate why customers would choose this product instead.

## Phase 2: Copywriting Output

Based on the analysis, produce the following deliverables:

### 1. Primary Statement
Use this canonical form:
> For **[audience]** who **[need/struggle]**, **[product]** is the **[category]** that **[key outcome]**. Unlike **[alternative]**, it **[differentiator]**.

### 2. One-liner
A plain-language version (≤12 words, no jargon) that a customer would say to a friend.

### 3. Three Variations
Benefit-led alternates in different angles (outcome-led, pain-led, identity-led) for A/B testing.

### 4. Before → After Transformation
A two-column table contrasting the painful status quo with the better state.

| Without [product] | With [product] |
|---|---|
| [the painful status quo] | [the better state] |

### 5. What to Avoid
List generic phrasings to cut (e.g., "all-in-one", "seamless", "next-generation").

## Quality Checks
- [ ] Names a specific audience — not "teams" or "businesses"
- [ ] Leads with the outcome/transformation, not features
- [ ] States the differentiator vs. a named alternative
- [ ] The one-liner is jargon-free and repeatable by a customer
- [ ] Claims are backed by (or flagged as needing) real proof

## Anti-Patterns
- Do not list features — a value prop is the outcome, features are the proof later.
- Do not write for everyone — pick the segment.
- Do not use empty superlatives ("revolutionary", "seamless").
- Do not skip the alternative — value is relative.
- Do not make an unbacked claim the headline.

## Notes
- Use the JTBD framework to focus on the progress the customer is trying to make.
- Value propositions are segment-specific.
- Test value props with real customers before finalizing.
