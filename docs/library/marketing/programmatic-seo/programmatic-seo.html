# Programmatic SEO

## Initial Assessment
1. Check for product marketing context: read `.agents/product-marketing.md` (or `.claude/product-marketing.md`, or `product-marketing-context.md`) if present. Also read root `contextus.md` when present and load only relevant modules.
2. Understand business context: product/service, target audience, conversion goal.
3. Assess opportunity: search patterns, number of potential pages, search volume distribution.
4. Evaluate competitive landscape: who ranks, what their pages look like, can you compete.

## Core Principles
- Unique value per page: not just swapped variables.
- Proprietary data wins: hierarchy from proprietary (strongest) to public (weakest).
- Clean URL structure: use subfolders, not subdomains.
- Genuine search intent match.
- Quality over quantity.
- Avoid Google penalties: no doorway pages, keyword stuffing, or duplicate content.

## Playbooks
Choose from: Templates, Curation, Conversions, Comparisons, Examples, Locations, Personas, Integrations, Glossary, Translations, Directory, Profiles. Layer multiple playbooks when appropriate.

## Implementation Framework
1. Keyword Pattern Research: identify repeating structure, variables, unique combinations; validate demand.
2. Data Requirements: identify data sources, first-party vs. scraped vs. licensed vs. public, update cadence.
3. Template Design: header with target keyword, unique intro, data-driven sections, related pages, CTAs. Ensure uniqueness via conditional content and original insights.
4. AI-Assisted Generation (optional): on grounded inputs (row JSON + rules), generate varied copy, FAQ expansions, and section emphasis per URL. Facts stay in the data layer; AI shapes phrasing and structure, not invented numbers.
5. Internal Linking Architecture: hub-and-spoke model, cross-links between related spokes, avoid orphan pages, XML sitemap, breadcrumbs with structured data.
6. Indexation Strategy: prioritize high-volume patterns, noindex very thin variations, manage crawl budget, separate sitemaps by page type.
7. Choose Build Platform: ensure the platform can hold page count, refresh data, render server-side HTML, branch on data, and control indexation per page. Prefer existing CMS if capable; otherwise serve on a subpath of the main domain.

## Quality Checks
Pre-launch: unique value per page, answers search intent, unique titles/meta, proper headings, schema markup, page speed, internal linking, no orphan pages, in XML sitemap, crawlable, no conflicting noindex.
Post-launch: track indexation rate, rankings, traffic, engagement, conversion. Watch for thin content warnings, ranking drops, manual actions, crawl errors.

## Common Mistakes
- Thin content from rigid mail-merge templates.
- Ignoring data quality.
- Creating orphan pages.
- Over-indexing low-value variations.
