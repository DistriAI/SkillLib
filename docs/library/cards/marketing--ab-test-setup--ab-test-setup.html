When to use

  • Use when a product change has enough eligible traffic for a randomized comparison and a measurable outcome. For low-volume launches or qualitative discovery, consider usability research or descriptive measurement instead of claiming causal…

When not to use

  • Clustered users, spillovers and repeated observations can invalidate independent-sample calculations.
  • Sequential monitoring needs a planned sequential method; fixed-horizon significance does not authorize repeated peeking.
  • A tracking gap or sample-ratio mismatch can invalidate inference despite a favorable primary metric.
  • This skill does not activate flags, publish variants or establish regulatory compliance automatically.

Conflict

The LeoYeAI copies (openclaw-marketing-skills and openclaw-master-skills) are nearly identical, providing a comprehensive guide with specific sample size tables, traffic allocation strategies, and implementation details (client vs. server-side). The sickn33 copy is a more rigorous, gate-based procedure that adds critical steps missing from the LeoYeAI versions, specifically a detailed 'Tracking Verification' checklist (event firing, variant attribution, de-duplication, randomization checks) and 'Refusal Conditions' for when a test cannot be validly run. Because the sickn33 version contains material safety and verification steps that the LeoYeAI versions lack, and the LeoYeAI versions contain specific reference data (sample size tables) that the sickn33 version omits, crowning one would hide a real alternative approach to the task.
