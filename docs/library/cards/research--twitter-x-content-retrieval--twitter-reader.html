twitter-reader

combined

Fetches Twitter/X post and Article content — text, author, engagement metrics and embedded media — downloading images locally and generating complete Markdown with image references. Use when retrieving a tweet's text or an X Article with images, or pulling post metadata for a Markdown/PKM record. Preferred over Jina alone for X Articles with images. Read Twitter/X for financial research through opencli: the user's home timeline, tweet search, trending topics, bookmarks, a user's recent tweets, threads, articles, profiles, followers and following, and notifications. Use this skill whenever the user wants to know what people are saying on Twitter/X or fintwit about a stock, topic, or market event, check their feed or bookmarks, see what's trending, or look up an @account and its posts. Read-only: it cannot post, like, retweet, reply, or follow.

When to use

  • retrieving a tweet's text
  • retrieving an X Article with images
  • pulling post metadata for a Markdown/PKM record
  • downloading images locally
  • generating complete Markdown with image references

When not to use

  • Jina alone for X Articles with images

Skill page

Conflict

The two skills share the name and the broad goal of reading Twitter/X, but they implement materially different procedures and tools. The first copy is a read-only financial-research skill built on opencli (browser-session reuse, opencli doctor, timeline/search/trending/bookmarks/profiles/notifications). The second copy is a content-fetching skill built on fxtwitter, Jina, and local scripts (fetch_article.py, fetch_tweet.py, fetch_tweets.sh) that downloads images and emits Markdown with YAML frontmatter. Neither copy is a reproduction, shortening, or wrapper of the other; crowning one would hide a real alternative workflow. They also disagree on prerequisites (Chrome + Browser Bridge + opencli vs uv + JINA_API_KEY + fxtwitter) and on what the skill can do (broad read-only browsing vs single-post/article fetching with media).
