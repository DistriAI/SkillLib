build

combined

Autonomous app-building skill — transforms plain-English descriptions into fully built, tested, and deployed applications via a 9-phase pipeline Use when developing a major feature: research the project, create a phased implementation plan, track progress and verify phase outcomes before declaring completion.

When to use

  • You need a structured workflow for building a major feature across research, planning, implementation, and tracking.
  • The task involves moving a feature through named phases such as `research`, `implementation`, `progress`, or `phase`.
  • You want one command to coordinate status, next steps, and phased delivery for a feature effort.

When not to use

  • Use this skill only when the task clearly matches the scope described above.
  • Do not treat the output as a substitute for environment-specific validation, testing, or expert review.
  • Validate feature IDs and destination containment before writing. Host-specific command and question tools are optional interfaces, not prerequisites.
  • Read-only status/research does not authorize deployment; existing plans and unrelated work must be preserved.

Skill page

Conflict

The two skills share the name 'build' and the high-level concept of a phased pipeline, but they define fundamentally different procedures and scopes. The first skill (davepoon) is an autonomous application builder that generates, tests, and deploys a new app from a plain-English description using specific tech stacks (Next.js, FastAPI, etc.). The second skill (sickn33) is a feature development workflow for existing projects that focuses on research, planning, and tracking progress for a specific feature, explicitly referencing a detailed guide and prohibiting deployment in read-only modes. Because they address different tasks (creating a new app vs. developing a feature in an existing codebase) and have conflicting operational constraints (one deploys, the other restricts deployment), crowning one would hide a valid alternative workflow.
