separate

Rigorous, defensible email-spoofability verdict and SPF supply-chain risk analysis computed from published DNS alone. Deepens the record-level SPF/DMARC/DKIM/BIMI/MTA-STS/DNSSEC fetch recipes in the offensive-osint arsenal (§16.14) with the reasoning that section doesn't do: a priority-ordered composite verdict for whether an attacker can actually land header-From-spoofed mail in an inbox, and by which vector (exact-domain vs subdomain) — grounded in the single most-misunderstood distinction in email security: the envelope MAIL FROM that SPF authenticates vs the visible header From: that only DMARC governs. Explains precisely why SPF -all/~all alone is NOT spoof-proof without DMARC enforcement, and why SPF +all bypasses DMARC even under p=reject pct=100. When to use

  • auditing a domain's real spoofing resistance
  • explaining why SPF -all does not mean covered
  • investigating an SPF PermError
  • investigating an unusually long include chain
  • evaluating a dead SPF include as a takeover lead
  • writing a defensible spoofability finding
  • reasoning about DMARC subdomain policy inheritance
  • reasoning about duplicate-record handling

When not to use

  • fetching raw records without prior retrieval
  • sending a spoofed test message
  • running an SMTP RCPT TO liveness check
  • auditing TLS/cert posture
  • AXFR / zone-transfer analysis
