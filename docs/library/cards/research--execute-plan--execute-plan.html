execute-plan

separate

Use when a research implementation plan exists in docs/superpapers/plans/ and the user is ready to execute it — collecting data, running analysis, producing outputs, writing the paper. Orchestrates task execution with replication-driven verification and two-stage review at phase boundaries.

When to use

  • A plan exists in `docs/superpapers/plans/`
  • User says "execute the plan", "run the plan", or "let's start implementing"
  • Transitioning from `write-plan` to implementation
  • Resuming execution of a partially-completed plan

When not to use

  • Creating directories or files without user confirmation
  • Deleting data
  • Resetting git state
  • Force-pushing
  • Overwriting files
  • Dispatching paper-writing to subagents
  • Skipping failed tasks
