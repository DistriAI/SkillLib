postgresql

combined

Administer PostgreSQL databases. Configure replication, backups, and performance tuning. Use when managing PostgreSQL deployments. Design a PostgreSQL-specific schema. Covers best-practices, data types, indexing, constraints, performance patterns, and advanced features

When to use

  • You need a reliable, ACID-compliant relational database.
  • Your application requires advanced features such as JSONB, full-text search, or CTEs.
  • You are setting up streaming replication or point-in-time recovery.
  • You need to tune an existing PostgreSQL deployment for better throughput.
  • Designing a schema for PostgreSQL
  • Selecting data types and constraints
  • Planning indexes, partitions, or RLS policies
  • Reviewing tables for scale and maintainability

When not to use

  • You are targeting a non-PostgreSQL database
  • You only need query tuning without schema changes
  • You require a DB-agnostic modeling guide

Conflict

The three copies cover two distinct, non-overlapping procedures. The BagelHole copy is an operational runbook for installing, configuring, securing, backing up, and replicating PostgreSQL servers. The rmyndharis and sickn33 copies are identical schema design guides covering data types, constraints, indexing, and normalization. Because the operational copy lacks schema design steps and the schema copies lack operational administration steps, crowning one would hide a real alternative procedure.
