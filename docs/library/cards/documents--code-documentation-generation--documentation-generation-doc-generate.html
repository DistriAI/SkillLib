Conflict

The two copies share the same core procedure (identify doc types, extract from code, generate consistent docs, reference the playbook), but they disagree on a key step and the second copy adds material constraints. The first copy instructs to 'Add automation (linting, CI) and validate accuracy' as a default step. The second copy explicitly changes this to 'add automation only when requested' and adds a specific 'Worked example and prerequisites' section that requires validating examples against actual routes/builds and recording which commands ran. It also adds a 'Limitations' section. Crowning the first copy would hide the second copy's more cautious approach to automation and its specific validation workflow, while crowning the second would lose the first's explicit default to add automation. Therefore, they must be combined to preserve both the default automation step and the conditional/validation alternative.
