verified-capability-evolver

separate

"Extends Capability Evolver with verification, rollback, and promotion gating. Use when an agent logs a learning, proposes a self-improvement, or wants to promote a learning to permanent memory. Before promotion, define a deterministic spec, verify actual output via SettlementWitness, then PASS → promote with receipt_id, FAIL → rollback and log counter-evidence, INDETERMINATE → hold for review." Verification is performed via an external SettlementWitness service. This skill defines the verification requirement and workflow but does not embed API clients or credentials; integration is handled by the runtime or connected verification layer.

When to use

  • logging learnings and errors
  • proposing self-improvement
  • promoting learning to permanent memory
  • defining deterministic verification specs
  • verifying actual output via SettlementWitness
  • rolling back failed promotions
  • holding indeterminate results for review
  • attaching receipts to promoted learnings

When not to use

  • embedding API clients or credentials
  • allowing permanent self-modification without verification
