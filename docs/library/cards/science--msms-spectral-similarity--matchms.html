matchms

combined

Mass spectrometry analysis. Process mzML/MGF/MSP, spectral similarity (cosine, modified cosine), metadata harmonization, compound ID, for metabolomics and MS data processing. Processes, cleans, compares, and searches tandem mass spectra with matchms. Use for MS/MS file I/O, metadata harmonization, peak filtering, spectral similarity, library matching, score matrices, and molecular-similarity networks. Use pyopenms instead for LC-MS feature detection or proteomics pipelines.

When to use

  • Use this skill when you need process, clean, and compare mass spectrometry (ms/ms) spectra with matchms; use when you need reproducible spectral filtering and similarity scoring for metabolomics workflows in a reproducible workflow.
  • Use this skill when a data analytics task needs a packaged method instead of ad-hoc freeform output.
  • Use this skill when the user expects a concrete deliverable, validation step, or file-based result.
  • Use this skill when `scripts/similarity_pipeline.py` is the most direct path to complete the request.
  • Use this skill when you need the `matchms` package behavior rather than a generic answer.

Conflict

The K-Dense copy is the most technically current and safe, pinning matchms 0.33.1 and correcting removed APIs (ModifiedCosine, add_losses, SpectrumProcessor callability). However, the other copies contain material steps and constraints that K-Dense lacks or presents differently: explicit import/export function names (load_from_mgf, save_as_msp), a broader list of similarity functions (FingerprintSimilarity, MetadataMatch), a packaged script execution path (similarity_pipeline.py), and a different dependency pinning strategy (matchms>=0.20,<1.0 vs ==0.33.1). Crowning K-Dense would hide the alternative workflow of using the packaged script and the broader similarity function set. The copies disagree on the correct similarity class name (ModifiedCosine vs ModifiedCosineGreedy) and the version pin, which are real conflicts.
