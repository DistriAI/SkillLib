batch

separate

Unified batch and async-job orchestration

When to use

  • Operating on many objects at once
  • Running or polling long async jobs
  • Preview-then-commit bulk edits
  • Composing multiple skill calls in one HTTP request
  • Executing bulk edits with dryRun or transactional modes
  • Managing async jobs via wait or poll endpoints
  • Retrying failed steps from a batch report

When not to use

  • Sending skills_batch to POST /skill/<name>
  • Using mode=plan
  • Executing more than 50 steps in a single call
  • Skipping the preview/confirm gate for batch_execute steps
