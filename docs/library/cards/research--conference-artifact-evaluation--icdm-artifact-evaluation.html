icdm-artifact-evaluation

separate

Use when packaging code, data, and logs for an ICDM (IEEE International Conference on Data Mining) paper - building the anonymized, history-scrubbed repository that the PDF must cite for a triple-blind Research Track submission, how the single-blind Applied Track changes what may be revealed, and the smoke checks that make an ICDM artifact reviewer-usable.

When to use

  • Packaging code, data, and logs for ICDM papers
  • Building anonymized, history-scrubbed repositories
  • Citing repositories in submitted PDFs
  • Handling triple-blind Research Track anonymity
  • Handling single-blind Applied Track requirements
  • Performing smoke checks for reviewer usability
  • Managing un-releasable data with synthetic proxies

When not to use

  • Running separate stamped artifact-badging tracks
