kotlin-control-flow

separate

Use when writing or reviewing Kotlin branching and control flow: when expressions, guard conditions, sealed type exhaustiveness, smart casts, nullable branching, early returns, or replacing complex if/else chains.

When to use

  • Kotlin branching
  • control flow
  • when expressions
  • guard conditions
  • sealed type exhaustiveness
  • smart casts
  • nullable branching
  • early returns

When not to use

  • introducing guards on unsupported Kotlin versions
  • forcing unrelated boolean checks into a subject when
  • removing an open-world fallback
  • flattening code that obscures cleanup, transactions, or errors
