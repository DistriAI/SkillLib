Use when hunting SQLi / NoSQLi on any target.

When to use

  • You need the recon, exploitation, or validation workflow described below — executed strictly inside the approved scope.

When not to use

  • Authorized scope only: the confirmation gate above is mandatory before any probing, exploitation, or credential-access command.

Conflict

Both copies share the same crown-jewel targets, attack-surface signals, and general SQLi/NoSQLi context, but they disagree on the core hunting methodology. The uphiago copy prescribes a broad, step-by-step workflow (error-based, boolean blind, time-based, NoSQL object injection, sqlmap automation, UNION escalation) and includes a large payload library. The sickn33 copy prescribes a different, more opinionated workflow: distrust target hints, prefer UNION over blind, and establish column count exhaustively via ORDER BY/UNION NULL enumeration before dumping. Because the sickn33 copy explicitly rejects the blind-first approach that the uphiago copy treats as a standard step, crowning one would hide a real alternative procedure. The sickn33 copy also adds a mandatory authorization gate and a source attribution that the uphiago copy lacks.
