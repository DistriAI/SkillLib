pufferlib

combined

Version-aware guidance for PufferLib reinforcement-learning environments, vectorization, policies, PuffeRL training, evaluation, and safe checkpoint review. Covers the native 5.0 build and environment API, published 3.0.0 Gymnasium/PettingZoo adaptation, and a pinned historical 4.0 profile. This skill should be used when working with reinforcement learning tasks including high-performance RL training, custom environment development, vectorized parallel simulation, multi-agent systems, or integration with existing RL environments (Gymnasium, PettingZoo, Atari, Procgen, etc.). Use this skill for implementing PPO training, creating PufferEnv environments, optimizing RL performance, or developing policies with CNNs/LSTMs.

When to use

  • **Training RL agents** with PPO on any environment (single or multi-agent)
  • **Creating custom environments** using the PufferEnv API
  • **Optimizing performance** for parallel environment simulation (vectorization)
  • **Integrating existing environments** from Gymnasium, PettingZoo, Atari, Procgen, etc.
  • **Developing policies** with CNN, LSTM, or custom architectures
  • **Scaling RL** to millions of steps per second for faster experimentation
  • **Multi-agent RL** with native multi-agent environment support

When not to use

  • Launching training via bundled plan schema
  • Importing arbitrary environments by dotted path
  • Installing or executing unreviewed environment packages
  • Passing W&B or Neptune credentials via CLI or config
  • Dumping all environment variables
  • Recursively searching for .env files

Skill page

Conflict

The two skills cover the same library but target fundamentally different versions and workflows. The first skill (K-Dense-AI) is a version-aware, security-focused guide that distinguishes between the native 5.0 C/CUDA build, the 3.0.0 PyPI release, and a pinned 4.0 source, emphasizing safe defaults, provenance verification, and synthetic CPU-only checks. The second skill (Vibe-Skills) is a practical, high-performance guide focused on the 3.0/4.0 era Python API, providing concrete code examples for PuffeRL training, PufferEnv development, and vectorization. They disagree on the primary API (native C vs Python/Gymnasium) and the recommended entry points (safe synthetic checks vs direct training loops). Combining them is necessary to provide a complete picture that includes both the security/provenance constraints of the first and the practical implementation details of the second.
