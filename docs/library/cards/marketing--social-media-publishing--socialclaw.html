Social media scheduling and publishing for AI agents. Use when the user wants to schedule posts, connect social accounts, upload media, or publish campaigns to X, LinkedIn, Instagram, Facebook Pages, TikTok, Discord, Telegram, YouTube, Reddit, WordPress, or Pinterest through SocialClaw. Agent-first social media publishing skill — schedule and publish posts across 13 platforms (X, LinkedIn, Instagram, Facebook Pages, TikTok, Discord, Telegram, YouTube, Reddit, WordPress, Pinterest) via a single workspace API key.

When to use

  • Use when the user wants to plan, schedule, or publish a social media campaign across multiple platforms.
  • Use when the user has a SocialClaw workspace API key and wants one workflow for X, LinkedIn, Instagram, Facebook, TikTok, Discord, Telegram, YouTube, Reddit, WordPress, or Pinterest.
  • Use when the user asks for social publishing automation that can validate schedules, attach media, and retrieve post performance metrics.

When not to use

  • Requires a valid SocialClaw workspace API key; do not attempt publishing without explicit user-provided credentials.
  • Treat every publish, schedule, delete, or account-changing action as state-changing: show the target platforms, content, media, and timing, then wait for explicit user confirmation before calling the service.
  • Platform availability, rate limits, analytics fields, and scheduling behavior depend on the upstream SocialClaw service.
  • This skill describes the publishing workflow; it does not replace platform-specific compliance, brand review, or legal approval before posting.

Conflict

The two copies describe the same SocialClaw service but provide materially different operational details. The davepoon copy is a concrete CLI reference with specific commands (socialclaw login, accounts connect, assets upload, validate, apply, status, analytics) and uses the SC_API_KEY environment variable. The sickn33 copy is a higher-level workflow guide that uses a different environment variable (SOCIALCLAW_API_KEY), includes a specific npm version (0.1.12), and adds critical safety constraints (explicit user confirmation for state-changing actions) that the first copy lacks. Crowning one would hide either the specific CLI syntax or the safety/compliance constraints.
