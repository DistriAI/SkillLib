sensys-reproducibility

separate

Use when making a SenSys result reproducible across a different testbed — capturing energy-measurement method, hardware and firmware provenance, sensor ground-truth protocol, and deployment conditions while the testbed is still live, and deciding early which traces and firmware can legally and safely ship.

When to use

  • capturing energy-measurement method
  • recording hardware and firmware provenance
  • documenting sensor ground-truth protocol
  • capturing deployment conditions
  • deciding which traces and firmware can ship
  • ensuring cross-hardware reproducibility
  • shipping recorded traces for analysis re-run

When not to use

  • reproducing results on the same testbed
  • resolving release constraints late
