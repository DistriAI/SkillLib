qframework-design

separate

Source-anchored design rules for QFramework v1.0.257 covering the four-layer architecture (Controller/System/Model/Utility), Command/Query/Event/BindableProperty core tools, and the CoreKit-family toolkits (UIKit/ResKit/ActionKit/PackageKit), distilled from QFramework.cs source and the official Doc.md tutorial with every rule citing a file/line anchor to guard against stale-memory hallucination.

When to use

  • Writing or reviewing QFramework architecture code
  • Registering Systems/Models/Utilities
  • Sending Commands/Queries/Events
  • Binding BindableProperty / BindableList / BindableDictionary
  • Choosing between core IOCContainer and Toolkits IOCKit
  • Choosing between architecture events and EasyEvent
  • Judging data placement in Model vs MonoBehaviour
  • Confirming Toolkits installation form and version

When not to use

  • Tasks not related to QFramework v1.0.257 design rules
