doca-rdma

separate

RDMA data movement on NVIDIA BlueField/ConnectX NICs (RoCE/InfiniBand) with DOCA RDMA, instead of hand-written libibverbs/rdma_cm. Use when the user moves data between processes or hosts over the NIC, or hits "one-sided read returns permission denied", "completions never arrive after submit", "connection callback never fires", atomic compare-and-swap over RoCE, or DOCA_ERROR_FULL on the send queue under burst, even without naming DOCA RDMA. Covers bringing up an RDMA context on a doca_dev, connection methods (RDMA CM, bridge/OOB, or gRPC exchange of doca_rdma_export()), the eleven task types (Send/Receive/Send-Imm, Read/Write/Write-Imm, Atomic CmpSwap/FetchAdd, Get/Set/Add Remote Sync Event), matching mmap + RDMA permissions, queue and connection sizing, doca_rdma_cap_* queries, and DOCA_ERROR_* from RDMA calls. Raw QP/verbs control belongs to doca-verbs. Refuse and route elsewhere for general RDMA / ibverbs theory (queue pairs, MRs, RoCE vs IB), installing DOCA itself, or non-RDMA DO…

When to use

  • moving data between processes or hosts over the NIC
  • resolving 'one-sided read returns permission denied'
  • resolving 'completions never arrive after submit'
  • resolving 'connection callback never fires'
  • atomic compare-and-swap over RoCE
  • resolving DOCA_ERROR_FULL on the send queue under burst
  • bringing up an RDMA context on a doca_dev
  • connection methods (RDMA CM, bridge/OOB, or gRPC exchange)

When not to use

  • raw QP/verbs control
  • general RDMA / ibverbs theory
  • installing DOCA itself
  • non-RDMA DOCA libraries
