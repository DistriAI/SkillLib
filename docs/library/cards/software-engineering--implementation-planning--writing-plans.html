writing-plans

combined

Use when you have a spec or requirements for a multi-step task, before touching code Write an executable work plan BEFORE starting a complex task — decomposed steps with verification points, risks pre-named, and explicit stop conditions — so execution becomes checking boxes instead of improvising. Use when a task will take many steps, when asked to plan before doing, when previous attempts sprawled or stalled, or before delegating work to subagents. Produces a plan document another agent (or future you) could execute without re-deriving the thinking. Pairs with executing-plans.

When to use

  • This skill is applicable to execute the workflow or actions described in the overview.

When not to use

  • Use this skill only when the task clearly matches the scope described above.
  • Do not treat the output as a substitute for environment-specific validation, testing, or expert review.
  • Stop and ask for clarification if required inputs, permissions, safety boundaries, or success criteria are missing.

Conflict

The four copies overlap on the core idea of writing a plan before coding, but they disagree on the plan's shape, granularity, and execution handoff. obra/superpowers is the most detailed TDD-oriented procedure (file structure, interfaces, checkbox steps, review focus, subagent-driven-development handoff). foryourhealth111-pixel and sickn33/agentic-awesome-skills are near-identical shorter TDD variants with a different save path and a two-option execution handoff. mohitagw15856 is a different planning method focused on outcome tests, risk tripwires, stop conditions, and a table format rather than TDD task steps. Crowning one would hide real alternatives.
