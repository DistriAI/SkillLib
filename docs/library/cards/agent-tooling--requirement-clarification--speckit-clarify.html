Structured clarification workflow for underspecified requirements. Use

When to use

  • Resolving ambiguities in feature specifications
  • Coverage-based questioning for missing decision points
  • Clarifying functional scope and behavior
  • Defining domain and data model details
  • Specifying non-functional quality attributes
  • Identifying integration and external dependencies
  • Handling edge cases and failure scenarios
  • Recording clarifications in the spec file

When not to use

  • Planning phase execution
  • Trivial stylistic preferences
  • Plan-level execution details unless blocking correctness
  • Exploratory spikes if user explicitly skips clarification
