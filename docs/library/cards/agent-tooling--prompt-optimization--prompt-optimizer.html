prompt-optimizer

combined

Transforms vague prompts or feature requests into precise, testable specifications using EARS (Easy Approach to Requirements Syntax) grounded in relevant domain theories (GTD, BJ Fogg, Gestalt). Use when requirements lack triggers or measurable outcomes, or the user asks to "optimize my prompt" / "improve this requirement" / "make this more specific". Creates, optimizes, and iteratively refines agent prompts, system prompts, developer prompts, and reusable prompt templates. Use when asked to improve a prompt, optimize a system prompt, rewrite an agent prompt, tune prompt wording, make a prompt more reliable, port prompts between OpenAI, Claude, or Gemini, or build prompt evals.

When to use

  • User provides vague feature requests ("build a dashboard", "create a reminder app")
  • Requirements lack specific conditions, triggers, or measurable outcomes
  • Natural language descriptions need conversion to testable specifications
  • User explicitly requests prompt optimization or requirement refinement

Skill page

Conflict

The three copies share the goal of improving prompts but use incompatible methods. daymade/claude-code-skills treats the task as converting vague feature requests into EARS requirements grounded in domain theories (GTD, Fogg, Gestalt) and outputs a Role/Skills/Workflows/Examples/Formats prompt. getsentry/skills treats the task as engineering an agent/system prompt with a contract, external context inventory, model-family strategy, and an iterative eval-driven optimization loop. mohitagw15856/pm-claude-skills treats the task as diagnosing a failing prompt and returning a full rewrite with a diagnosis table, change rationale, and a small test set. Because each copy contains material steps and constraints the others lack, and they disagree on the core workflow (EARS transformation vs eval loop vs diagnosis/rewrite), crowning one would hide real alternatives.
