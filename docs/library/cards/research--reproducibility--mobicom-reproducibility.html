mobicom-reproducibility

separate

Use when making a MobiCom result reproducible on a different testbed — recording radio, hardware, channel, and mobility provenance as the runs happen, characterizing the variance that over-the-air measurement introduces, and deciding early which traces, firmware, and deployment data can legally and safely ship for artifact evaluation.

When to use

  • recording radio, hardware, channel, and mobility provenance
  • characterizing over-the-air measurement variance
  • deciding which traces, firmware, and deployment data can ship
  • planning hardware-optional reproduction paths
  • creating trace-replay or downscaled configurations
  • auditing reproducibility readiness

When not to use

  • bit-identical reruns
  • reconstructing provenance after testbed teardown
