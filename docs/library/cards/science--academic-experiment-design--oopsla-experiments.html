oopsla-experiments

separate

Use when designing or auditing the evaluation of an OOPSLA paper — matching evidence type to claim type across the venue's spread (benchmarks, corpus studies, case studies, user studies, mechanized proofs), building baselines and workloads that survive the SIGPLAN checklist, and sizing experiments to the round calendar.

When to use

  • designing OOPSLA paper evaluation
  • auditing OOPSLA paper evaluation
  • matching evidence type to claim type
  • building baselines and workloads
  • sizing experiments to the round calendar
  • benchmarking against strongest baselines
  • corpus studies with selection rules
  • user studies and field data design

When not to use

  • writing OOPSLA paper prose
  • general software engineering tasks
  • non-OOPSLA venue evaluations
