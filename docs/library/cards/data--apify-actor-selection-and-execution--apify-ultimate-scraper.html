Skill page

Conflict

The two copies describe the same high-level task (select an Apify Actor, fetch schema, run, deliver results) but they disagree on the execution mechanism and include material steps the other lacks. The apify/agent-skills copy is the canonical procedure: it mandates the Apify CLI, defines universal command rules (--json, --user-agent, 2>/dev/null), provides a dynamic actor search fallback, and includes a workflow-guide routing table. The sickn33 copy is a different implementation: it requires the mcpc CLI, hard-codes a large Actor catalog, adds a pricing-approval gate, and uses a checklist-driven workflow. Crowning one would hide a real alternative execution path and omit either the CLI rules or the pricing/actor-catalog constraints.
