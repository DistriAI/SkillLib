icra-artifact-evaluation

separate

Use when packaging the artifacts behind an ICRA paper — ROS packages, controllers, simulation environments, trained policies, CAD and PCB files, datasets, and trial logs — into something a robotics reviewer or reader can actually run or audit, given that ICRA has no formal artifact-badging track to certify it for you.

When to use

  • Packaging ICRA paper artifacts
  • Inventorying robotics artifact layers
  • Creating Docker/pinned environments
  • Writing CLAIMS.md
  • Preparing anonymized review states
  • Staging public acceptance states
  • Documenting hardware-dependent artifacts
  • Managing datasets and logs

When not to use

  • Formal artifact-badging certification
  • Tasks not related to ICRA artifact packaging
