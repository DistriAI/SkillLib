good

separate

Use when the user needs to turn a recurring release checklist into a structured Markdown runbook with inputs, outputs, review gates, and handoff notes. Do not use for live deployment or credential handling.

When to use

  • turn a recurring release checklist into a structured Markdown runbook
  • extract pre-release, in-release, and post-release check items
  • annotate owners, risks, rollback conditions, and acceptance criteria
  • generate Markdown runbook and JSON checklist

When not to use

  • live deployment
  • credential handling
  • executing deployment commands
  • reading secrets
  • replacing human release owners
