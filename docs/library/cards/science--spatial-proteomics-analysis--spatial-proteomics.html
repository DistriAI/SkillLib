spatial-proteomics

combined

Analyzes multiplexed antibody-imaging data (CODEX/PhenoCycler, MIBI-TOF, IMC, CyCIF, Opal/Vectra mIF) as continuous protein intensity rather than transcript counts, using scimap and squidpy. Use when choosing an intensity transform/normalization (arcsinh cofactor vs z-score vs percentile -- NOT log1p-of-counts) and correcting channel spillover and antibody-batch effects; deciding whether to phenotype by gating or by clustering on intensities; recognizing that a bounded antibody panel makes marker absence uninformative; treating whole-cell segmentation (Mesmer) as the dominant error source; and knowing which platform applies and when to defer to the imaging-mass-cytometry skills for the IMC pipeline.

When to use

  • Analyzing spatial proteomics data
  • Working with multiplexed imaging data
  • Analyzing protein spatial patterns
  • Integrating spatial proteomics with transcriptomics
  • Phenotyping cells by gating or clustering
  • Correcting channel spillover and antibody-batch effects
  • Choosing intensity transform/normalization

When not to use

  • IMC-specific analysis

Skill page

Conflict

The two skills cover the same task but with different emphases and conflicting technical guidance. The first copy (OpenClaw) provides a concise, code-heavy workflow using scimap and squidpy, but it recommends log1p transformation, which is generally incorrect for continuous protein intensity data. The second copy (GPTomics) provides a much deeper conceptual framework, explicitly warning against log1p and recommending arcsinh/z-score, and it details platform-specific confounds and segmentation errors. Because the first copy's preprocessing step is technically flawed compared to the second, and the second copy contains substantial material (platform decision logic, governing principles) missing from the first, crowning one would hide the correct approach or the practical code structure. They must be combined to get the correct preprocessing and the complete workflow.
