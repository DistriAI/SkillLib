golang-naming

separate

Go (Golang) naming conventions — covers packages, constructors, structs, interfaces, constants, enums, errors, booleans, receivers, getters/setters, functional options, acronyms, test functions, and subtest names. Use this skill when writing new Go code, reviewing or refactoring, choosing between naming alternatives (New vs NewTypeName, isConnected vs connected, ErrNotFound vs NotFoundError, StatusReady vs StatusUnknown at iota 0), debating Go package names (utils/helpers anti-patterns), or asking about Go naming best practices. Also trigger when the user mentions MixedCaps vs snake_case, ALL_CAPS constants, Get-prefix on getters, or error string casing. Do NOT use for general Go implementation questions that don't involve naming decisions.

When to use

  • writing new Go code
  • reviewing or refactoring
  • choosing between naming alternatives
  • debating Go package names
  • asking about Go naming best practices
  • MixedCaps vs snake_case
  • ALL_CAPS constants
  • error string casing

When not to use

  • general Go implementation questions that don't involve naming decisions
