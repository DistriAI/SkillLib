sensys-topic-selection

separate

Use when deciding whether a project belongs at SenSys after the 2026 merger absorbed IPSN and IoTDI — testing whether the contribution is a built, measured sensing/embedded/IoT/on-device-AI system rather than a pure algorithm, a mobile-networking mechanism, or an offline ML result, and routing misfits to MobiCom, MobiSys, or an ML/DSP venue.

When to use

  • deciding whether a project belongs at SenSys
  • testing if contribution is a built, measured sensing/embedded/IoT/on-device-AI system
  • routing misfits to MobiCom, MobiSys, or an ML/DSP venue
  • evaluating low-power networked sensing and mote-class protocols
  • evaluating IoT design/implementation and edge deployments
  • evaluating on-device / TinyML models with measured footprint on an MCU
  • resolving post-merger boundary calls for on-device AI vs ML papers
  • determining fit for sensing systems measured on real hardware

When not to use

  • pure algorithm with no embedded realization
  • mobile-networking mechanism
  • offline ML result
  • wireless link, PHY/MAC, or over-the-air networking mechanism
  • mobile-platform / smartphone systems contribution
  • new estimator/algorithm with no embedded realization
  • datacenter/OS/networking systems result
  • simulation-only or single-run results
