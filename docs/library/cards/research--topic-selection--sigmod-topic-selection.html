sigmod-topic-selection

separate

Use when judging whether a project belongs at SIGMOD's research track, comparing it against PVLDB's rolling model, ICDE, PODS, KDD, CIDR, and TODS, weighing the industrial track for deployment papers, and testing whether the contribution is genuinely a data-management result rather than an application that touches data.

When to use

  • judging whether a project belongs at SIGMOD's research track
  • comparing against PVLDB's rolling model
  • comparing against ICDE, PODS, KDD, CIDR, and TODS
  • weighing the industrial track for deployment papers
  • testing whether the contribution is genuinely a data-management result
  • distinguishing data-management advances from application papers
  • deciding between SIGMOD and PVLDB based on cadence and failure cost
  • identifying data-management primitives for research-track fit

When not to use

  • application papers that use databases heavily but advance only their application
  • mining or ML methods where data infrastructure is incidental
  • formal semantics, complexity, or lower bounds without data-management focus
  • provocative architecture visions with thin evaluation
  • broad data-engineering results with weak database framing
