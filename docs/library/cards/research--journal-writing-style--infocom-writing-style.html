infocom-writing-style

separate

Use when revising an IEEE INFOCOM paper for a networking problem and system model stated up front, theorems or protocol design that pay off, evaluation proportional to the claim, defensive writing that pre-empts objections (because there is no rebuttal), double-blind wording, and disciplined use of the tight IEEEtran two-column page budget.

When to use

  • revising an IEEE INFOCOM paper
  • stating networking problem and system model
  • ensuring theorems or protocol design pay off
  • making evaluation proportional to claims
  • defensive writing to pre-empt objections
  • maintaining double-blind wording
  • managing the IEEEtran two-column page budget

When not to use

  • opening with a technology-trend paragraph
  • using adjectives like 'significantly improves' without evidence
  • leaving assumptions hidden or introduced only in evaluation
  • using untuned baselines
  • failing to state the regime where results do not hold
