doca-flow-perf

separate

Use this skill when the user measures control-plane insertion throughput of DOCA Flow with the doca_flow_perf binary on x86 host or Arm cores — selecting a configs/ JSON policy, weighing the DPDK-versus-DOCA backend, running the smoke iteration then the eval loop, interpreting CPU cycles plus num_pushed / num_failed, or capturing the four-tuple (DOCA release, firmware, JSON policy, worker config) that makes an insertion figure defensible. Also load it for implied asks like "5-tuple hairpin insert figure", "flow-perf result mismatches release notes", "DPDK-vs-DOCA comparison", or "install variance too high". Refuse and route to the proper owner for live-app optimization (doca-flow-tune), DPA-side measurement (doca-flow-dpa-perf), wire throughput or latency, or library-internal pipe semantics.

When to use

  • measuring control-plane insertion throughput
  • selecting configs/ JSON policy
  • weighing DPDK-versus-DOCA backend
  • running smoke iteration and eval loop
  • interpreting CPU cycles and num_pushed / num_failed
  • capturing four-tuple for defensible insertion figures
  • 5-tuple hairpin insert figure
  • DPDK-vs-DOCA comparison

When not to use

  • live-app optimization
  • DPA-side measurement
  • wire throughput or latency
  • library-internal pipe semantics
  • diagnosing live Flow application
