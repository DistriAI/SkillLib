gatk-variant-calling

combined

Call germline SNPs and indels with GATK HaplotypeCaller and the GVCF joint-genotyping workflow. Covers the local-reassembly + PairHMM mechanism (why HC beats pileup callers on indels), the -ERC GVCF reference-confidence model and <NON_REF> allele, BQSR-vs-DRAGSTR and --dragen-mode error modeling, allele-specific (AS_) annotations, and edge cases (ploidy, Mutect2 mitochondria mode, sex chromosomes/PAR, contamination gating). Use when deciding whether to use HaplotypeCaller vs a pileup or DRAGEN caller, whether BQSR still earns its place, whether to call per-sample GVCFs for a cohort, or how to handle non-diploid, mitochondrial, sex-chromosome, or contaminated samples. Not for post-calling filtering depth (see variant-calling/filtering-best-practices) or cohort joint-genotyping scaling (see variant-calling/joint-calling).

When to use

  • germline SNP/indel calling
  • GVCF workflow for cohorts
  • joint genotyping
  • variant quality score recalibration (VQSR)
  • calling variants with GATK HaplotypeCaller
  • single-sample calling
  • target intervals (Exome/Panel)
  • hard filtering

Skill page

Conflict

The two skills cover the same core GATK HaplotypeCaller workflow but diverge significantly in scope and depth. The first copy (FreedomIntelligence) is a procedural 'how-to' guide that includes specific commands for VQSR and Hard Filtering, which are often considered part of the 'calling' pipeline in older best practices. The second copy (GPTomics) is a conceptual and decision-oriented guide that explains the *mechanism* of HaplotypeCaller (local reassembly, PairHMM), provides a decision tree for choosing between tools (HC vs Mutect2 vs DRAGEN), and explicitly excludes filtering depth, pointing to other skills. The first copy lacks the mechanistic explanation and the decision tree for edge cases (ploidy, somatic), while the second copy lacks the specific VQSR/Hard Filter command examples that the first provides. Combining them yields a complete skill that covers both the 'why/when' (decision tree, mechanism) and the 'how' (commands for calling and filtering).
