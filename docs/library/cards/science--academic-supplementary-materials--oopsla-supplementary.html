oopsla-supplementary

separate

Use when deciding what rides along with an OOPSLA submission beyond the 23-page body — appendices, full proofs or mechanizations, extended tables, anonymized code — keeping the package double-anonymous, self-consistent with the PDF, and honest about what reviewers are obliged to read versus what a revision can absorb.

When to use

  • deciding what rides along with an OOPSLA submission
  • managing appendices, full proofs, or mechanizations
  • managing extended tables and anonymized code
  • keeping the package double-anonymous
  • ensuring self-consistency with the PDF
  • determining what reviewers are obliged to read
  • structuring appendices as promotable units for revision

When not to use

  • rescue material for body overrun
  • unfinished experiments flagged preliminary
  • de-anonymizing generosity such as screenshots or grant-numbered names
