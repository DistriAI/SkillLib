# Material Skill

This skill covers two distinct domains. Determine the user's intent to select the correct procedure.

## 1. Unity Material Manipulation
Use this section when the user wants to edit 3D material properties in Unity (Built-in/URP/HDRP).

### Operating Mode
- **Approval**: Mutating skills require user grant.
- **Query**: `material_get_properties` and `material_get_keywords` run without grant.

### Key Procedures
- **Create Material**: Use `material_create` with `name` and optional `shaderName`/`savePath`.
- **Set Color**: Use `material_set_color` with `r`, `g`, `b`, `a` in range 0-1. Note: This edits the material asset, not just the object instance.
- **Set Properties**: Use `material_set_float`, `material_set_int`, `material_set_vector`, or `material_set_keyword`.
- **Batch Operations**: Use `*_batch` variants for 2+ objects.

### Guardrails
- Do not use non-existent skills like `material_set_metallic`; use `material_set_float` with `propertyName="_Metallic"`.
- Targeting a GameObject edits the shared material asset. To avoid side effects, create a new material, set properties, then assign it.

## 2. Material Design System Authoring
Use this section when the user wants to create or review Material Design guidelines for web/mobile UI.

### Workflow
1. Restate design intent.
2. Define tokens (color, typography, spacing) and foundations.
3. Specify component anatomy, states (default, hover, focus, active, disabled), and interaction behavior.
4. Include accessibility acceptance criteria (WCAG 2.2 AA).
5. Add anti-patterns and migration notes.
6. End with a QA checklist.

### Quality Gates
- Anchor rules to tokens or thresholds, not ambiguous adjectives.
- Prioritize accessibility over aesthetics when conflicts arise.
- Use "must" for non-negotiable rules and "should" for recommendations.
