# Design System

This skill covers three distinct aspects of design system work: generation, extraction, and implementation invariants.

## 1. Generation (Mobile/Expo)
Use this when creating a new brand system for an Expo/React Native app.
- **Artifacts**: `brand/design-system.md` (spec), `brand/tokens.ts` (Tamagui tokens), `brand/design-system.html` (gallery).
- **Inputs**: Brand docs, logos, URLs, or Figma links.
- **Modes**: Standalone, refresh, reskin, or dark-mode addition.

## 2. Extraction (Web)
Use this when reverse-engineering a design system from an existing source.
- **Sources**: Live URL (via Playwright), local HTML, screenshot, or Google Stitch project.
- **Process**: 
  1. Identify source.
  2. Extract raw data (HTML/CSS, screenshots).
  3. Analyze tokens (colors, typography, components, spacing).
  4. Synthesize into a semantic `DESIGN.md`.

## 3. Implementation Invariants
Use these rules when building components or pages to ensure quality.
- **Token Architecture**: Map all colors to primitives (Foreground, Background, Border, Brand, Semantic). Never hardcode hex.
- **Typography**: Clear hierarchy via size, weight, and letter-spacing. Use monospace with `tabular-nums` only for aligned data.
- **Loading Order**: Prioritize above-the-fold content. Self-host WOFF2 fonts. Preload critical assets. Lazy-load below-the-fold.
- **FOUT Prevention**: Never use `font-display: swap` for critical text. Gate visibility on `document.fonts.ready` with a safety timeout.
- **Graceful Loading**: Avoid ugly intermediate states for slow-loading content (images, video, WebGL). Use placeholders and progressive enhancement.
