# Devil's Advocate

Use this skill to critically challenge a work product. Choose the track that matches the input.

## Track A: Thesis / Argument Stress Test

Use when the user provides a thesis, investment memo, research conclusion, or business decision and asks for a pressure test, bear case, red team, or blind-spot check.

### Step 0 · Input Confirmation
1. **Thesis**: Normalize to "X will because Y Z" and confirm with the user. If running in a sub-agent without a user, mark it "unconfirmed" and continue.
2. **Evidence materials**: List of file paths, directories, or URLs. Verify readability; report unreadable items.
3. **Purpose**: Self-check before a meeting, or evaluating someone else's plan. This sets the tone of the narrative layer.

### Step 1 · Decompose Assumptions
- Split the thesis into **explicit assertions** and **implicit assumptions**, numbered A1, A2, …
- Tag each with **type** (factual / predictive / mechanistic) and **load-bearing** status (would the conclusion materially change if this were false?).
- Non-load-bearing assumptions are deferred to an appendix; they do not enter counter-evidence retrieval.
- In single-context mode, retrieve counter-evidence for at most the top 8 load-bearing assumptions by importance; in fan-out mode, retrieve for all.

### Step 2 · Retrieve Counter-Evidence per Assumption
For each assumption ask:
1. What in the materials directly weakens, contradicts, or introduces uncertainty?
2. If this assumption were true, what evidence should be present in the materials but is absent?

Source credibility order: official filings / primary data → expert interviews / call transcripts → analyst / broker reports → authoritative media → aggregators / social media (leads only, not anchors).

Hard rules:
- Every counter-argument must cite: source file/URL + location (page/line/section) + verbatim excerpt.
- If no counter-evidence is found, write "No counter-evidence found in the given materials" and leave citations empty. Note that this means "materials do not cover it," not "assumption is true."
- Assign each piece of evidence to the single assumption it most directly refutes; cross-reference by ID if needed.

### Step 3 · Structured Findings (Audit Layer)
Write `da_findings.json` (or user-specified path) with this shape:

```json
{
  "run_metadata": {
    "thesis_normalized": "…",
    "materials": ["…"],
    "coverage": "Enumerated N / Retrieved M / Not retrieved K / Deferred J"
  },
  "findings": [
    {
      "assumption_id": "A1",
      "assumption": "…",
      "type": "factual | predictive | mechanistic",
      "counter_argument": "…",
      "citations": [{"doc": "…", "loc": "…", "excerpt": "…"}],
      "rebuttal": "… | null",
      "missing_evidence": "… | null",
      "base_rate": "… | null",
      "risk_flag": "High | Medium | Low",
      "signpost": "…"
    }
  ],
  "deferred_assumptions": ["…"]
}
```

- `risk_flag` measures the counter-argument's lethality to the thesis, not probability. High = core conclusion fails; Medium = magnitude/timeline significantly impaired; Low = marginal correction. If more than half are High, re-rank and re-assign.
- `base_rate` is filled only when the given materials support a reference class; otherwise null. Do not fabricate or retrieve externally.

### Step 4 · Narrative Report (Delivery Layer)
Write `da_report.md` and deliver in chat:
- Open with a coverage statement (materials, assumptions retrieved vs. not, material bias) and the 2-3 most damaging counter-arguments. Do not render an overall verdict.
- Group by theme following the thesis's reasoning chain, not by A1/A2 order. Use inline [n] citations.
- Each argument 2-3 sentences, institutional analyst tone: factual, restrained, no exclamation marks or rhetorical questions.
- End with: References (with assumption IDs), Surviving assumptions (no counter-evidence found; note "not found ≠ true"), Coverage appendix (deferred and un-retrieved assumptions).

### Step 5 · Falsification Signal List
For each High/Medium assumption, one line: what to watch, where to look, what reading is an alarm. In no-materials mode, cover all load-bearing assumptions.

### Red Lines
- Do not judge the thesis as overall right/wrong or give buy/sell advice.
- Counter-evidence strength is bounded by the evidence: if materials only support "introduces uncertainty," do not write "falsifies."
- Tone: factually neutral throughout.
- Coverage honesty: state what was and was not retrieved.

### Fan-out Mode (main session only)
1. Main session completes Steps 0-1.
2. Dispatch a sub-agent per assumption (or 2-3 assumptions) with: assumption text, material paths, the two questions from Step 2, the JSON schema and risk_flag anchors from Step 3, and the verbatim-citation / no-fabrication rules. Each sub-agent writes `da_findings_A<id>.json` and returns a summary.
3. Main session merges into `da_findings.json`, deduplicating evidence by assigning it to the higher-risk assumption.

## Track B: Slide Deck / Lecture Pedagogical Review

Use when the user provides a lecture file or slide deck and asks for a design challenge, pedagogical review, or devil's-advocate pass on presentation quality.

### Setup
1. Read the target lecture file.
2. Read the knowledge base in `.claude/rules/` for notation conventions and narrative arc.
3. If applicable, read adjacent lectures for narrative continuity.

### Generate 5-7 Challenges from These Categories
1. **Ordering**: "Could students understand this better if we showed X before Y?"
2. **Prerequisites**: "Do students have the background for this notation at this point?"
3. **Gaps**: "Should we include an intuitive example before this formal proof?"
4. **Alternative Presentation**: "Here are 2 other ways to visualize/present this concept."
5. **Notation Conflict**: "This symbol conflicts with earlier lecture usage."
6. **Cognitive Load**: "This slide has too many new symbols. Can we split?"
7. **Book Vision**: "If this becomes a book chapter, does this section stand alone?"

### Output Format

```markdown
# Devil's Advocate: [Lecture Title]

## Challenges

### Challenge 1: [Category] — [Short title]
**Question:** [The specific pedagogical question]
**Why it matters:** [What could go wrong]
**Suggested resolution:** [Specific action]
**Slides affected:** [Numbers or titles]
**Severity:** [High / Medium / Low]

[Repeat for 5-7 challenges]

## Summary Verdict
**Strengths:** [2-3 things done well]
**Critical changes:** [0-2 changes before teaching]
**Suggested improvements:** [2-3 nice-to-have changes]
```

### Principles
- Be specific: reference exact slides and notation.
- Be constructive: every challenge has a suggested resolution.
- Be honest: if the deck is good, say so.
- Prioritize: notation conflicts > missed metaphors.
- Think like a student: where do they get lost?
