# Auto Review Loop: Autonomous Research Improvement

> Do not wrap this skill in /loop, /schedule, or CronCreate. It already loops internally and the reviewer carries round-to-round memory in one threadId. An external timer resets reviewer memory each tick.

Autonomously iterate: review → implement fixes → re-review, until an independent reviewer gives a policy-approved positive assessment or MAX_ROUNDS is reached.

## Context: $ARGUMENTS

## Constants

- MAX_ROUNDS = 4
- POSITIVE_THRESHOLD: score >= 6/10 AND verdict in {"ready", "almost"} — both must hold.
- REVIEW_DOC: review-stage/AUTO_REVIEW.md (cumulative log). Fall back to ./AUTO_REVIEW.md for legacy projects.
- REVIEWER_MODEL = gpt-6-astra — Default model for the Codex backend. Must be an OpenAI model.
- REVIEWER_BACKEND — With no reviewer directive, start as auto; Step -1 runs a two-call native marker/challenge probe. A bound Copilot CLI root session uses copilot-native; an unbound host keeps codex. Explicit directives (codex, oracle-pro, agy, manual, copilot) bypass the probe.
- OUTPUT_DIR = review-stage/ — All review-stage outputs go here. Create if missing.
- HUMAN_CHECKPOINT = false — When true, pause after each round's review and present score + weaknesses. User can approve, customize, skip, or stop.
- COMPACT = false — When true, read EXPERIMENT_LOG.md and findings.md instead of full logs; append key findings to findings.md after each round.
- REVIEWER_DIFFICULTY = medium — medium (default), hard (adds Reviewer Memory + Debate Protocol), nightmare (adds direct repo read + Adversarial Verification).
- RENDER_HTML = true — When true, auto-render AUTO_REVIEW.md to HTML on loop termination via /render-html with --no-review.

> Nightmare + Manual incompatibility: If REVIEWER_BACKEND = manual and REVIEWER_DIFFICULTY = nightmare, STOP with an error message.

## State Persistence (Compact Recovery)

Long-running loops may hit the context window limit. Persist state to REVIEW_STATE.json after each round:

```json
{
  "round": 2,
  "threadId": "019cd392-...",
  "status": "in_progress",
  "last_score": 5.0,
  "last_verdict": "not ready",
  "pending_experiments": ["screen_name_1"],
  "timestamp": "2026-03-13T21:00:00"
}
```

Write this file at the end of every Phase E. Overwrite each time. On completion, set status to completed.

## Workflow

### Initialization

1. Check for REVIEW_STATE.json:
   - Missing or status=completed: fresh start.
   - status=in_progress and timestamp older than 24 hours: fresh start (delete file).
   - status=in_progress and timestamp within 24 hours: resume. Read state, read AUTO_REVIEW.md, check pending experiments, resume from next round.
2. Read project narrative documents, memory files, and prior review documents. When COMPACT=true and compact files exist, read findings.md + EXPERIMENT_LOG.md instead.
3. Read recent experiment results.
4. Identify current weaknesses and open TODOs.
5. Initialize round counter = 1 (unless recovered).
6. Create/update AUTO_REVIEW.md with header and timestamp.

### Loop (repeat up to MAX_ROUNDS)

#### Phase A: Review

Branch on REVIEWER_BACKEND. For codex, send comprehensive context via mcp__codex__codex with model_reasoning_effort xhigh. Prompt the reviewer to act as a senior ML reviewer, score 1-10, list critical weaknesses ranked by severity, specify minimum fixes, and state readiness. For round 2+, use mcp__codex__codex-reply with the saved threadId.

#### Phase B: Parse Assessment

Save the FULL raw response verbatim. Extract score, verdict, and action items.

STOP CONDITION: If score >= 6 AND verdict in {ready, almost} → stop loop, document final state.

#### Human Checkpoint (if enabled)

If HUMAN_CHECKPOINT=true, present review results and wait for user input. Parse approval, custom instructions, skip, or stop.

#### Phase C: Implement Fixes

Implement the approved fixes. Update code, experiments, and documentation.

#### Phase D: Verify

Verify that fixes address the identified weaknesses.

#### Phase E: Document and Persist

Append the round's review, fixes, and verification to AUTO_REVIEW.md. Write REVIEW_STATE.json. If RENDER_HTML=true and loop is terminating, render to HTML.

- wanshuiyin/Auto-claude-code-research-in-sleep uses gpt-6-astra and a backend probe; brycewang-stanford/Auto-Empirical-Research-Skills uses gpt-5.4 with no probe. The probe and gpt-6-astra are used here as they are the more evolved configuration.
- brycewang-stanford/Auto-Empirical-Research-Skills includes REVIEW_STATE.json persistence; wanshuiyin/Auto-claude-code-research-in-sleep does not. The persistence protocol is included here as it is a material step absent from the other copy.
