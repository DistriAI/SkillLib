# Cohort Analysis & Retention Explorer

## Purpose
Analyze user engagement and retention patterns by cohort to identify trends in user behavior, feature adoption, and long-term engagement. Combine quantitative insights with qualitative research recommendations.

## Required Inputs
Before starting, confirm or request any missing inputs. Do not invent numbers, benchmarks, or schema details.

| Input | What to ask if missing |
|---|---|
| Analysis objective | Retention improvement / LTV modeling / behavioral segmentation / churn prediction |
| Product or feature | What is being analyzed? |
| Cohort definition | What groups users into a cohort? (acquisition month, signup channel, plan tier, feature adoption date) |
| Observation window | How many periods to track? (e.g., 12 months, 8 weeks) |
| Key metric | What is measured per cohort? (retention rate, revenue, engagement score, feature usage) |
| Available data | Paste schema, table names, or describe available metrics — do not assume |
| Baseline or target | Are there existing retention benchmarks or targets to compare against? |

If the user cannot supply real data, produce the framework with clearly marked placeholders (`[X%]`, `[£X]`, `[N users]`) and note which sections require real data to complete.

## Process

### Step 1: Confirm Inputs and Validate Data
- Surface any ambiguity before producing output (e.g., conflicting cohort definitions, missing observation window).
- Accept CSV, Excel, JSON, or SQL query results with user cohort information.
- Verify data structure: cohort identifier, time periods, engagement metrics.
- Check for missing values and data quality issues.
- Summarize key statistics (cohort sizes, date ranges, metrics available).

### Step 2: Define Cohorts
- Establish entry event, exit criteria, and exclusions so cohorts are mutually exclusive.
- If any cohort falls below a minimum size threshold for statistical reliability, flag it explicitly and exclude it from trend conclusions.

### Step 3: Build Retention Table and Curves
- Complete or template the period-by-period retention matrix.
- Calculate cohort retention rates and engagement trends.
- Identify the plateau period where the curve flattens; if the observation window is too short to show a plateau, declare it explicitly.
- Identify retention curves, drop-off patterns, and anomalies.
- Compute feature adoption rates across cohorts.
- Calculate period-over-period changes.

### Step 4: Project LTV
- Use only observed retention data for LTV estimation.
- Mark if data is insufficient for reliable projection.

### Step 5: Segment by Behavior
- Create mutually exclusive behavioral segments.
- Identify the activation threshold for each segment.

### Step 6: Surface Churn Signals
- List observable churn signals with lead time and intervention mapping.

### Step 7: Compare Cohorts Over Time
- Evaluate whether product changes are reflected in newer cohorts.
- Compare cohort performance to establish baselines.

### Step 8: Create Visualizations
- Generate retention heatmaps (cohorts vs. time periods).
- Create line charts showing cohort progression.
- Build comparison charts for feature adoption.
- Visualize drop-off points and engagement trends.
- Output as interactive charts or static images.

### Step 9: Identify Insights and Patterns
- Spot one or more significant patterns:
  - Early churn in specific cohorts
  - Late-stage engagement changes
  - Feature adoption clusters
  - Seasonal or temporal trends
- Highlight surprising findings and deviations.

### Step 10: Prioritize Recommendations
- Link each recommendation to a specific cohort finding or segment.
- Recommend qualitative research methods:
  - Targeted user interviews with churning users
  - Feature usage surveys with engaged cohorts
  - Session replays of key interaction patterns
  - Win/loss analysis for high vs. low retention cohorts
- Design follow-up quantitative studies.
- Suggest A/B tests or feature experiments.

### Step 11: Provide SQL Reference
- Adapt the query template to the user's actual schema if supplied.

### Step 12: Execute Quality Checks
- Verify all items on the checklist before delivering output.

## Tips for Best Results
1. **Include time dimension**: Provide data across multiple time periods.
2. **Define cohort clearly**: Make cohort grouping explicit (signup month, feature launch date, etc.).
3. **Provide context**: Explain product changes, launches, or events during the period.
4. **Multiple metrics**: Include retention, engagement, feature usage, revenue, etc.
5. **Sufficient data**: At least 3-4 cohorts for meaningful pattern identification.
6. **Request specific output**: Ask for visualizations, Python scripts, or research recommendations.

## Key Capabilities
- **Data Reading**: Import CSV, Excel, JSON, SQL query results
- **Retention Analysis**: Calculate and visualize retention rates over time
- **Cohort Comparison**: Compare metrics across cohort groups
- **Anomaly Detection**: Flag unusual patterns or drop-offs
- **LTV Estimation**: Project lifetime value from observed retention
- **Behavioral Segmentation**: Create mutually exclusive segments with activation thresholds
- **Python Scripts**: Generate reusable analysis code for ongoing analysis
- **Visualizations**: Create heatmaps, charts, and interactive dashboards
- **Research Design**: Suggest targeted follow-up studies and interview approaches
- **Statistical Summary**: Provide quantitative metrics and correlation analysis
