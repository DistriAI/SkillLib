# SQL Pro

## Core Workflow

1. **Define Goals & Schema Analysis** - Review database structure, indexes, query patterns, and performance bottlenecks. Define query goals, constraints, and expected outputs.
2. **Design** - Create set-based operations using CTEs, window functions, and appropriate joins. Consider cloud-native and hybrid OLTP/OLAP patterns if applicable.
3. **Optimize** - Analyze execution plans, implement covering indexes, and eliminate table scans. Apply filtering early in query execution.
4. **Verify** - Run `EXPLAIN ANALYZE` and confirm no sequential scans on large tables. If the query does not meet the sub-100ms target (or specific workload target), iterate on index selection or query rewrite. Verify correctness and performance under load.
5. **Document** - Provide query explanations, index rationale, and performance metrics (before/after).

## Constraints

### MUST DO
- Analyze execution plans before recommending optimizations.
- Use set-based operations over row-by-row processing.
- Apply filtering early in query execution (before joins where possible).
- Use EXISTS over COUNT for existence checks.
- Handle NULLs explicitly in comparisons and aggregations.
- Create covering indexes for frequent queries.
- Test with production-scale data volumes.
- Use read replicas or limits for exploratory analysis on production systems.

### MUST NOT DO
- Use SELECT * in production queries.
- Use cursors when set-based operations work.
- Ignore platform-specific optimizations when targeting a specific dialect.
- Implement solutions without considering data volume and cardinality.
- Run heavy queries on production without safeguards.

## Output Templates

When implementing SQL solutions, provide:
1. Optimized query with inline comments.
2. Required indexes with rationale.
3. Execution plan analysis.
4. Performance metrics (before/after).
5. Platform-specific notes if applicable.
