# Property-Based Testing

## 1. Strategic Assessment

An example test asserts one point. A property asserts a rule over the whole input domain. This trade is worth making when the code has an algebraic shape (inverse, invariant, oracle). If the code has no such shape, use example tests.

**Check for buried properties:**
- Calculations wrapped in I/O
- Strings built by concatenation
- In-place mutations

If a property is buried, refactor to expose a seam before concluding PBT is not applicable.

**Property Strength Ordering (Weakest to Strongest):**
1. No crash
2. Type preservation
3. Invariant
4. Idempotence
5. Roundtrip / Oracle

*Rule:* Assert the strongest property the code supports. "No crash" alone rarely justifies the dependency.

## 2. Property Catalog

| Property | Formula | Where it applies |
|---|---|---|
| Roundtrip | `decode(encode(x)) == x` | Serialization, conversion pairs |
| Inverse | `f(g(x)) == x` | encrypt/decrypt, compress/decompress |
| Oracle | `new(x) == reference(x)` | Optimization, refactoring |
| Idempotence | `f(f(x)) == f(x)` | Normalization, formatting, sorting |
| Invariant | Holds before and after | Any transformation, contract state |
| Easy to verify | `is_sorted(sort(x))` | Complex algorithms with cheap checkers |
| Commutativity | `f(a, b) == f(b, a)` | Binary and set operations |
| Associativity | `f(f(a,b), c) == f(a, f(b,c))` | Combining operations |
| Identity | `f(x, e) == x` | Operations with a neutral element |

## 3. Common Pitfalls

- **Tautology:** `assert add(a, b) == a + b` restates the implementation. Pick a property that constrains the function without recomputing it. *Exception:* `f(x) == f(x)` is a valid determinism property for non-pure functions (e.g., serializers over dicts, hashing).
- **Vacuity:** `assume()` that filters out nearly every input passes without exercising anything. Push constraints into the strategy/generator so valid inputs are produced directly.

## 4. Implementation: TypeScript/JavaScript (fast-check)

### Installation
```bash
npm install -D fast-check
# or
bun add -d fast-check
```

### Basic Structure
```typescript
import { test } from 'vitest'
import * as fc from 'fast-check'

test('reverse twice returns original', () => {
  fc.assert(
    fc.property(
      fc.array(fc.integer()),
      (arr) => {
        expect(reverse(reverse(arr))).toEqual(arr)
      }
    )
  )
})
```

### Key Generators
- **Numbers:** `fc.integer()`, `fc.nat()`, `fc.float()`, `fc.double()`
- **Strings:** `fc.string()`, `fc.hexaString()`, `fc.emailAddress()`
- **Collections:** `fc.array()`, `fc.set()`, `fc.record()`
- **Complex:** `fc.tuple()`, `fc.oneof()`, `fc.option()`, `fc.chain()`

### Custom Generators
```typescript
const userArbitrary = fc.record({
  id: fc.nat(),
  name: fc.string({ minLength: 1 }),
  email: fc.emailAddress(),
  roles: fc.array(fc.constantFrom('admin', 'user'), { minLength: 1 })
})
```

## 5. Implementation: Python (Hypothesis)

### Installation
```bash
pip install hypothesis
```

### Basic Structure
```python
from hypothesis import given, strategies as st

def test_reverse_twice(arr):
    assert reverse(reverse(arr)) == arr

@given(st.lists(st.integers()))
def test_reverse_property(arr):
    assert reverse(reverse(arr)) == arr
```

### Key Strategies
- **Numbers:** `st.integers()`, `st.floats()`, `st.decimals()`
- **Strings:** `st.text()`, `st.from_regex()`
- **Collections:** `st.lists()`, `st.dictionaries()`, `st.tuples()`
- **Complex:** `st.builds()`, `st.one_of()`, `st.just()`

## 6. Debugging Failures

When a property test fails:
1. **Shrinking:** The library minimizes the failing input. Review the minimal counterexample.
2. **Diagnosis:** Determine if the failure is a wrong property (tautology/vacuity) or a genuine bug.
3. **Fix:** Either correct the property assertion or fix the code bug.

## 7. Library Selection

- **TypeScript/JavaScript:** fast-check
- **Python:** Hypothesis
- **Rust:** proptest
- **Java:** jqwik
- **Solidity:** Echidna or Medusa

If the project does not already use a PBT library, adding one is a dependency decision. Offer it once with the specific property you would write, and take the answer either way.
