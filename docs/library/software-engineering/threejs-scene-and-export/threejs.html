# Three.js — Scene Building and Export Skill

## When to use
- Building interactive 3D scenes: product spins, hero scenes, shaders, 3D data viz.
- Parsing a Three.js scene graph for export: part partitioning, mesh baking, InstancedMesh expansion, per-part OBJ export, URDF articulation.
- Debugging performance, resource leaks, or resize issues in WebGL scenes.

## Core mental model
- Create a `Scene`, `Camera` (Perspective/Orthographic), and `WebGLRenderer`.
- `Mesh` = `Geometry` + `Material`; add lights for non-unlit materials.
- Render loop: `requestAnimationFrame(animate)` → update time-based animations, controls, mixers → `renderer.render(scene, camera)`.

## Scene building (interactive web)
1. Setup renderer: `new THREE.WebGLRenderer({ canvas, antialias, alpha })`; `renderer.setSize(width, height, false)`; `renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))`.
2. Camera: `camera.aspect = width / height; camera.updateProjectionMatrix()`.
3. Scene graph: `scene.add(object)`; use `object.position/rotation/scale`.
4. Load assets: `GLTFLoader`, `TextureLoader`, `DRACOLoader`.
5. Controls: `OrbitControls`, `PointerLockControls`, or custom pointer handlers.
6. Cleanup in SPAs: `geometry.dispose()`, `material.dispose()`, `texture.dispose()`, `renderer.dispose()`; remove event listeners; cancel RAF.
7. Handle resize: update renderer size, pixel ratio, camera aspect, and projection matrix.
8. Respect `prefers-reduced-motion`: render a still frame or slow updates.

## Scene-graph parsing and export
1. Load the module, call `createScene()`, then `updateMatrixWorld(true)`.
2. Treat named `THREE.Group` nodes as parts/links.
3. Assign each mesh to its nearest named ancestor.
4. Do not merge meshes from nested named groups into parents.
5. Skip empty parts; sort part names for determinism.
6. Bake world transforms into geometry before export:
   - `root.updateMatrixWorld(true)`
   - `geom = mesh.geometry.clone(); geom.applyMatrix4(mesh.matrixWorld)`
   - If indexed, convert to non-indexed; compute vertex normals if missing.
7. Expand `InstancedMesh` by multiplying `matrixWorld` with each instance matrix.
8. Convert Y-up to Z-up if needed: `geom.applyMatrix4(new THREE.Matrix4().makeRotationX(-Math.PI / 2))`.
9. Export per-part OBJ: collect meshes owned by each part, do not traverse into child named groups, merge baked geometries, write `<part>.obj`.
10. For URDF: use named groups as links; parent is nearest named ancestor; joint type defaults to `fixed` unless evidence suggests `revolute`/`prismatic`; sort link and joint names.

## Common pitfalls
- Not handling resize → stretched/cropped rendering.
- Too high devicePixelRatio → mobile GPU meltdown.
- Leaking WebGL resources (not disposing) → crashes after route changes.
- Loading huge textures/models → slow start; use compressed textures, Draco/KTX2, smaller maps.
- Using too many lights/shadows → expensive; fake lighting with baked textures when possible.
- Forgetting to bake world transforms before export → incorrect geometry positions.
- Merging nested named groups → incorrect part partitioning.

## What to ask the user
- Is this decorative (hero) or functional 3D (product viewer)?
- Target devices: mobile? older iPhones?
- Asset format availability (glTF, HDRI, textures) and file size constraints.
- Accessibility/reduced motion requirements.
- For export: desired output format (OBJ, URDF), axis convention, and part naming rules.
