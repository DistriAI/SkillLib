## Autonomous Testing Priority

**Try workflow bypasses before brute force — they're faster and more likely to succeed.**

### Pattern 1 — Skip the MFA step entirely (most automatable)
1. Login with valid credentials → receive a "pre-MFA" session state.
2. Without completing MFA, directly access a protected resource (`/dashboard`, `/api/me`, `/account/profile`).
3. If the response returns user data → MFA is enforced only in the UI, not server-side = Critical.

```bash
curl -s -b "session=PRE_MFA_SESSION" https://target.com/dashboard
```

### Pattern 2 — OTP replay (reuse a consumed code)
1. Complete a valid MFA flow to get a working OTP.
2. Log out, log in again with the same credentials.
3. Submit the same OTP again.
4. If accepted → OTP is not invalidated after use.

### Pattern 3 — Response Manipulation
1. Enter wrong OTP → capture response in Burp.
2. Change `{"success":false}` → `{"success":true}` (or 401 → 200).
3. Forward → if app proceeds → client-side only MFA check.

### Pattern 4 — Partial / incremental validation (prefix oracle)
If a guessed full code is rejected, test whether the server validates the OTP **prefix-by-prefix** instead of all-or-nothing.
1. Submit a 1–3 digit value (e.g. `otp=1`, then `otp=12`, …) — for a POST verify endpoint the code goes in the **request body**, not the URL query string.
2. If a *correct* prefix gives a DIFFERENT response than a wrong one (a success/flag, a distinct message, or a different length/timing), the validator leaks correctness one chunk at a time.
3. Walk the code digit-by-digit: keep the prefix that "responds correct," append 0–9, repeat. This collapses 10^6 brute force to ~10×N guesses (≤60 for a 6-digit code).
**CRITICAL — stay in ONE session:** re-authenticating regenerates the OTP, throwing away your prefix progress. Do the entire sweep against a single established MFA session; never re-login between guesses.

### Pattern 5 — No Rate Limit on OTP (full brute force)
```bash
ffuf -u "https://target.com/api/verify-otp" \
  -X POST -H "Content-Type: application/json" \
  -H "Cookie: session=YOUR_SESSION" \
  -d '{"otp":"FUZZ"}' \
  -w <(seq -w 000000 999999) \
  -fc 400,429 -t 5
```
Only attempt full brute force with evidence of no rate limit AND a small key space.

### Pattern 6 — Race on MFA Verification
```python
import asyncio, aiohttp

async def verify(session, otp):
    async with session.post("https://target.com/api/mfa/verify",
                            json={"otp": otp}) as r:
        return r.status, await r.text()

async def race():
    cookies = {"session": "YOUR_SESSION"}
    async with aiohttp.ClientSession(cookies=cookies) as s:
        results = await asyncio.gather(*[verify(s, "123456") for _ in range(30)])
        for status, body in results:
            print(status, body)
asyncio.run(race())
```
Fire ~30 concurrent submissions of the SAME OTP to hit the TOCTOU window. Best done as a single-packet / 20+ HTTP-2-stream attack (Turbo Intruder).

### Pattern 7 — Backup Code Brute Force
```bash
ffuf -u "https://target.com/api/mfa/verify-backup" \
  -X POST -H "Content-Type: application/json" \
  -H "Cookie: session=YOUR_SESSION" \
  -d '{"backup_code":"FUZZ"}' \
  -w <(seq -w 00000000 99999999) \
  -fc 400,401,429 -t 10 -p 0.1-0.5
```
Key checks: purely numeric? format-locked? per-IP rate limiting? invalidated after use?

### Pattern 8 — "Remember This Device" Trust Escalation
1. Complete MFA once on Device A (attacker's browser).
2. Capture the "remember device" cookie.
3. Present that cookie from a new IP/browser.
4. If MFA skipped = device trust not bound to IP/UA = ATO from any location.

### Pattern 9 — OAuth Device Code Flow MFA Bypass
Device authorization grant (RFC 8628) skips interactive user-agent, meaning MFA challenge is NEVER presented.

Detection:
```bash
curl -s "https://target.com/.well-known/oauth-authorization-server" | jq ".device_authorization_endpoint"
```
If present, test if MFA is bypassed on the device code grant.

### Pattern 10 — MFA via SMS (backup factor downgrade)
Check if SMS factor has no rate limit or if the SMS endpoint can be abused to downgrade the MFA factor.

## MFA Chain Escalation
```
Rate limit bypass + no lockout = ATO (Critical)
Response manipulation = client-side only check = Critical
Skip MFA step = auth flow bypass = Critical
OTP reuse = persistent session hijack = High
```

## Proof
A session token or protected resource data in the response without completing MFA confirms the bypass.
