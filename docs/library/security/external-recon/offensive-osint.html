# Offensive OSINT & Recon

## 1. Authorization & Safety
- **Mandatory Confirmation Gate**: Before any active probe, the user must state the exact target and confirm written authorization.
- **Scope**: Use for authorized external recon, bug bounty, or red-team engagements.
- **Do NOT**: Use for active exploitation, post-exploitation, or unauthorized targets.

## 2. Workflow
1. **Define Scope**: Determine if the target is a domain/org (technical) or a person/entity (human).
2. **Select Category**:
   - **Human/OSINT**: Use tools for username/email/phone/people search (e.g., Sherlock, Hunter.io, TruePeopleSearch).
   - **Technical Recon**: Use the operational arsenal for subdomain enum, secret scanning, and infrastructure mapping.
3. **Execute**:
   - **Technical**: Load specific reference files (probes, secret-patterns, identity-fabric) as needed.
   - **Human**: Pivot on discovered artifacts (emails, usernames) to social media and breach data.
4. **Archive**: Log all findings in JSONL with `run_id`, timestamps, and SHA-256 hashes.

## 3. Technical Recon Arsenal
- **Probes**: Use wordlists for Swagger, GraphQL, and cloud buckets.
- **Secrets**: Scan for 80+ patterns (AWS, GCP, AI keys, etc.).
- **Identity**: Enumerate Entra, Okta, ADFS, and M365 endpoints.
- **Mobile**: Perform APK static analysis for embedded secrets and misconfigurations.

## 4. Human-Centric OSINT
- **Username/Email**: Use Sherlock, Maigret, and Hunter.io.
- **Social Media**: Use platform-specific tools (Picuki, snscrape, etc.).
- **Breach Data**: Check Have I Been Pwned, DeHashed, and HudsonRock.

## 5. Output Format
- Findings must include: `id`, `module`, `asset_key`, `severity`, `confidence`, `evidence` (URL + timestamp + hash), and `remediation`.
