# SOP Writer

Produce a formal, audit-ready SOP suitable for regulated industries, ISO certification, GCP compliance, or operational scaling.

## When to Use
- Writing GCP-compliant SOPs for laboratory or clinical workflows
- Writing operational SOPs for any department or function
- Creating work instructions or operating manuals
- When a reproducible SOP with explicit roles, steps, and control points is required

## When Not to Use
- One-station shop-floor work instructions (use a dedicated shop-floor SOP skill if available)
- When required inputs are missing — ask the user to provide them first
- When the task goes outside the documented scope

## Required Inputs
| Field | Required | Example |
|---|---|---|
| SOP title | Yes | SOP-001: Blood Sample Processing |
| Department / function | Yes | Clinical Laboratory |
| Process description | Yes | End-to-end description of the procedure |
| Regulatory or quality standard | Yes | ISO 15189, GCP, ISO 9001, GMP |
| Roles involved | Yes | Technician, Supervisor, QA |
| Tools or equipment used | Yes | Centrifuge, pipette, LIMS |

## Output Structure

Produce the SOP using the following sections. Adapt section numbering and depth to the regulatory context.

### Document Header
| Document ID | [SOP-XXX] |
|---|---|
| Title | [Title] |
| Department | [Department] |
| Version | 1.0 |
| Effective date | [Date] |
| Review date | [Date] |
| Status | Draft / Under review / Approved |

### 1. Purpose
1-2 sentences explaining why this SOP exists.

### 2. Scope
**Applies to:** [Roles, departments, locations]
**Does not apply to:** [Explicit exclusions]

### 3. Definitions
| Term | Definition |
|---|---|
| [Term] | [Plain English definition] |

### 4. Responsibilities
| Role | Responsibility |
|---|---|
| [Role] | [Specific responsibility] |

### 5. Required Materials / Tools / Access
- [Item]

### 6. Procedure
| Step | Action | Responsible | Record/Output |
|---|---|---|---|
| 6.1.1 | [Imperative action] | [Role] | [What to record] |

Rules for procedure steps:
- Write every step in imperative form ("Open the system", not "The system should be opened")
- Each step contains exactly one action
- Every step is assigned to a specific role

### 7. Quality Checks
| Check point | What to verify | Pass criteria | If fail |
|---|---|---|---|
| [After step X] | [What to check] | [What good looks like] | [What to do] |

### 8. Non-Conformance
1. [Immediate action]
2. [Who to notify]
3. [How to document deviation]

### 9. References
[Related SOPs, policies, standards]

### 10. Document History
| Version | Date | Author | Changes |
|---|---|---|---|
| 1.0 | [Date] | [Name] | Initial release |

### Signature Page (for GCP / ISO 15189 contexts)
Include a signature block for author, reviewer, and approver with date fields.

## Quality Checklist
- [ ] All steps written in imperative form
- [ ] Each step has exactly one action
- [ ] Role specified for every step
- [ ] Quality checkpoints at critical stages
- [ ] Non-conformance process defines who to notify and how to document
- [ ] Document history table and review date are included
- [ ] No hardcoded credentials or API keys
- [ ] Output does not expose sensitive information
- [ ] Input file paths validated (no ../ traversal)

## Anti-Patterns
- Do not write steps that contain more than one action
- Do not omit a role from any step
- Do not skip the non-conformance section
- Do not produce an SOP without a review date and version history
- Do not use passive voice in procedure steps

## Error Handling
- If required inputs are missing, state exactly which fields are missing and request only the minimum additional information
- If the task goes outside the documented scope, stop instead of guessing
- Do not fabricate files, citations, data, or execution outcomes

## Response Template
For non-trivial requests, structure the response as:
1. Objective
2. Inputs Received
3. Assumptions
4. Workflow
5. Deliverable (the SOP)
6. Risks and Limits
7. Next Checks

## Example
Input: Blood sample processing, Clinical Laboratory, ISO 15189
Output: Complete SOP with document header, purpose, scope, definitions, responsibilities, materials, procedure steps, quality checks, non-conformance, references, document history, and signature page
