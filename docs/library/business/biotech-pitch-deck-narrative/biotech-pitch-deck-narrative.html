# Biotech Pitch Deck Narrative

## When to Use
- Preparing biotech pitch decks, investor-facing section rewrites, or fundraising story structures.
- Translating scientific and clinical data into investor-friendly narratives.
- Preparing investor Q&A scaffolds or risk-aware messaging.

## Do NOT Use When
- Scientific conference presentations (use technical language).
- Regulatory submission documents (use formal FDA/EMA formats).
- Internal R&D communications (use full scientific detail).
- Patent applications (use precise legal/scientific terminology).

## Workflow

1. **Confirm Scope and Inputs**
   - Financing stage (pre-seed, seed, series-a, series-b, series-c, ipo).
   - Investor audience (generalist-vc, biotech-specialist, pharma-corp).
   - Available scientific evidence, clinical data, and market context.
   - Non-negotiable claim boundaries and regulatory constraints.
   - Whether the request is a full narrative, a single section rewrite, or high-level messaging guidance.

2. **Validate Evidence and Stop Conditions**
   - If scientific support or market context is missing, stop and request the minimum additional inputs.
   - Do not invent data. All claims must be tied to supplied evidence.
   - Explicitly note where evidence is missing or claims require validation.

3. **Translate Science to Business Language**
   - Convert technical concepts into investor-friendly language using translation strategies:
     - "CRISPR-Cas9 gene editing" → "Precision genetic medicine platform"
     - "Phase II clinical data" → "De-risked asset with human proof-of-concept"
     - "Off-target effects" → "Industry-leading specificity profile"
     - "MOA via JAK-STAT pathway" → "Novel mechanism addressing root cause"
   - Preserve scientific accuracy while adapting tone for the target audience.

4. **Build Narrative Architecture**
   Structure the deck narrative in this order:
   1. **Hook** (30 seconds): Why this, why now, why you.
   2. **Problem**: Unmet medical need, current standard limitations, market size.
   3. **Solution**: Technology/platform, mechanism of action, key differentiation.
   4. **Traction**: Clinical data, partnerships, validation to date.
   5. **Market**: Size, competition, your advantage.
   6. **Team**: Track record, why you will succeed.
   7. **Ask**: Funding amount, use of proceeds, milestones.

5. **Optimize for Stage and Audience**
   - **Seed** ($500K-$2M): Focus on team, vision, early validation.
   - **Series A** ($10-30M): Focus on proof-of-concept data, IP position, market entry.
   - **Series B** ($30-75M): Focus on Phase 2/3 data, BD traction, team expansion.
   - **Series C/IPO** ($100M+): Focus on commercial execution, registration trials, launch prep, revenue path.
   - Calibrate technical depth and risk framing for generalist vs. specialist investors.

6. **Produce Output**
   - Return a structured deck narrative that separates assumptions, value claims, evidence status, and open diligence gaps.
   - Include stage- and audience-aware positioning cues.
   - Explicitly note where evidence is missing or claims require validation.
   - If using a script, run `python scripts/main.py --stage <stage> --audience <audience> --input <path> --output <path>`.
   - If using a narrative engine, use `BiotechNarrativeEngine` to generate and calibrate the narrative.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `--stage` | string | No | `seed` | Financing stage |
| `--audience` | string | No | `generalist-vc` | Target investor audience |
| `--input` | string | No | - | Input deck or source file path |
| `--output` | string | No | `optimized_narrative.json` | Output file path |

## Security and Risk Checklist
- [ ] No hardcoded credentials or API keys.
- [ ] No unauthorized file system access.
- [ ] Claims are tied to supplied evidence, not invented data.
- [ ] Regulatory and clinical statements remain bounded.
- [ ] Output path reviewed before overwrite.
- [ ] Error handling does not imply completed diligence.
- [ ] Market-sizing claims require user-supplied assumptions.
- [ ] Legal and scientific review remains mandatory.
