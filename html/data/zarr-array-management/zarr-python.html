# Zarr Python

## When to use

Use for chunked scientific arrays, hierarchical stores, codecs, sharding, partial reads, cloud object storage, and NumPy/Dask/Xarray interoperability. This guide targets **Zarr-Python 3.4.0** (released 2026-09-15) but includes general best practices for Zarr 3.x. The package version and on-disk format are separate: Zarr 3 reads/writes formats 2 and 3; new arrays default to format 3.

## Install

```bash
# For Zarr 3.4.0 (Recommended for new projects)
uv pip install "zarr==3.4.0" "numpy==2.5.3"

# For general Zarr 3.x
uv pip install zarr

# Optional remote backends and migration CLI:
uv pip install "zarr[remote,cli]" "fsspec" "s3fs" "gcsfs"
```

Commit the project's resolved lockfile. Local examples use tiny synthetic arrays; remote snippets are illustrative and require a real authorized store.

## Workflow

1. **Inspect**: Check shape, dtype, axis names, coordinates, units, missing-value convention, format, and codec availability. Preserve sample IDs and axis order.
2. **Choose Chunks**: 
   - Aim for ~1MB per chunk for optimal performance (e.g., 512x512 for float32).
   - Align chunk shape with access patterns (e.g., if reading rows, make chunks span columns).
   - For sharding, choose shard dimensions that are multiples of chunk dimensions.
   - Benchmark representative data.
3. **Create Destination**: Use `overwrite=False` or `mode="w-"` for new stores. Use `mode="r"` for inspection. `"w"` destroys existing content.
4. **Write Bounded Blocks**: Assign one writer per stored chunk (or shard). Serialize metadata, append, and resize operations. Avoid materializing the entire array in memory.
5. **Validate**: Reopen read-only and compare values, dtype, shape, coordinates, units, masks, and metadata. An unwritten chunk reads as `fill_value`; a successful open alone does not prove data completeness.
6. **Consolidate**: For completed group hierarchies, optionally consolidate metadata. Format-3 consolidation is experimental; refresh it after metadata changes.

## Basic Array Roundtrip

```python
import numpy as np
import zarr
from zarr.codecs import BloscCodec

expected = np.arange(96, dtype="float32").reshape(12, 8)
z = zarr.create_array(
    "array.zarr", shape=expected.shape, dtype=expected.dtype,
    chunks=(4, 4), zarr_format=3,
    compressors=BloscCodec(cname="zstd", clevel=5, shuffle="bitshuffle"),
    dimension_names=("sample", "feature"),
    attributes={"units": "arbitrary", "source": "synthetic example"},
)
for start in range(0, z.shape[0], 4):
    z[start:start + 4] = expected[start:start + 4]

reopened = zarr.open_array("array.zarr", mode="r")
np.testing.assert_array_equal(reopened[:], expected)
assert reopened.dtype == expected.dtype
assert reopened.metadata.dimension_names == ("sample", "feature")
```

**Note**: `create_array` takes either `data=` or `shape=` plus `dtype=`. The format-3 numeric default is a bytes serializer followed by **ZstdCodec**, not Blosc. Set a codec explicitly for reproducibility.

## Creation and Indexing

```python
import numpy as np
import zarr

# Creation
z = zarr.create_array(None, data=np.arange(80).reshape(10, 8), chunks=(2, 4))
zeros = zarr.zeros((10, 8), chunks=(2, 4), dtype="f4")
ones = zarr.ones((10, 8), chunks=(2, 4), dtype="f4")
filled = zarr.full((10, 8), fill_value=42, chunks=(2, 4), dtype="i4")
like = zarr.zeros_like(z)

# Indexing
# Coordinate indexing pairs corresponding coordinates
np.testing.assert_array_equal(z.vindex[[0, 5], [2, 7]], [2, 47])
# Orthogonal indexing is a product
assert z.oindex[[0, 5], [2, 7]].shape == (2, 2)
# Block indexing
assert z.blocks[0, 0].shape == (2, 4)
```

**Warning**: Negative-step slices are unsupported. `np.asarray(z)`, `np.sum(z)`, or `z[:]` can materialize the entire logical dataset; use bounded selections or lazy reductions.

## Resize and Append

```python
import numpy as np
import zarr

series = zarr.create_array(None, shape=(0, 8), chunks=(2, 8), dtype="f4")
series.append(np.ones((2, 8), dtype="f4"), axis=0)
series.resize((4, 8))  # A tuple; append must match all non-appended dimensions.
assert series.shape == (4, 8)
```

**Note**: Shrinking removes chunks outside the new shape, but values in retained boundary chunks can reappear on re-expansion. Resize is not secure erasure.

## Chunking Strategies

### Aligning Chunks with Access Patterns

Chunk shape dramatically affects performance.

```python
# If accessing rows frequently (first dimension)
z = zarr.zeros((10000, 10000), chunks=(10, 10000))  # Chunk spans columns

# If accessing columns frequently (second dimension)
z = zarr.zeros((10000, 10000), chunks=(10000, 10))  # Chunk spans rows

# For mixed access patterns (balanced approach)
z = zarr.zeros((10000, 10000), chunks=(1000, 1000))  # Square chunks
```

**Performance Example**: For a (200, 200, 200) array, reading along the first dimension:
- Using chunks (1, 200, 200): ~107ms
- Using chunks (200, 200, 1): ~1.65ms (65x faster!)

### Sharding for Large-Scale Storage

When arrays have millions of small chunks, use sharding to group chunks into larger storage objects.

```python
from zarr.codecs import ShardingCodec, BytesCodec
from zarr.codecs.blosc import BloscCodec

z = zarr.create_array(
    store='data.zarr',
    shape=(100000, 100000),
    chunks=(100, 100),  # Small chunks for access
    shards=(1000, 1000),  # Groups 100 chunks per shard
    dtype='f4'
)
```

**Benefits**:
- Reduces file system overhead from millions of small files.
- Improves cloud storage performance (fewer object requests).

**Important**: Entire shards must fit in memory before writing.

## Compression

Zarr applies compression per chunk.

```python
from zarr.codecs.blosc import BloscCodec
from zarr.codecs import GzipCodec, ZstdCodec, BytesCodec

# Configure Blosc codec
z = zarr.create_array(
    store='data.zarr',
    shape=(1000, 1000),
    chunks=(100, 100),
    dtype='f4',
    codecs=[BloscCodec(cname='zstd', clevel=5, shuffle='shuffle')]
)

# Use Gzip compression
z = zarr.create_array(
    store='data.zarr',
    shape=(1000, 1000),
    chunks=(100, 100),
    dtype='f4',
    codecs=[GzipCodec(level=6)]
)

# Disable compression
z = zarr.create_array(
    store='data.zarr',
    shape=(1000, 1000),
    chunks=(100, 100),
    dtype='f4',
    codecs=[BytesCodec()]
)
```

**Tips**:
- **Blosc** (default): Fast compression/decompression, good for interactive workloads.
- **Zstandard**: Better compression ratios, slightly slower than LZ4.
- **Gzip**: Maximum compression, slower performance.
- **LZ4**: Fastest compression, lower ratios.
