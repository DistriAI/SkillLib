# Multi-Agent Code Review Orchestration

## When to Use
Use this skill when a codebase or diff needs review across multiple disciplines such as correctness, security, architecture, and performance.

## Inputs and Scope
1. **Define Scope**: Pin the repository, base/head commits, changed paths, and intended behavior.
2. **Authorization Check**: Determine if the user has authorized delegation to independent agents and if the host environment supports it. If not, conduct the review sequentially.

## Review Process
1. **Context Analysis**: Read the complete diff and directly affected call paths. Identify relevant perspectives (e.g., security, performance) based on the change.
2. **Agent Selection (Optional)**: If delegation is authorized, select specialized reviewers (Code Quality, Security, Architecture, Performance). Assign each a bounded question, owned paths, and a time/effort limit.
3. **Execution**: 
   - **Parallel**: Run independent reviews concurrently if authorized.
   - **Sequential**: Run reviews one by one if delegation is not authorized or for dependent insights.
4. **Evidence Collection**: Record findings with exact locations, triggers, consequences, and reproduction steps. Keep hypotheses separate from demonstrated failures.

## Synthesis and Resolution
1. **Deduplication**: Merge insights by root cause, not wording.
2. **Conflict Resolution**: Resolve disagreements through code inspection or test execution. Do not use weighted voting or confidence scores as evidence of correctness.
3. **Validation**: Reproduce important findings centrally. Preserve original failing results; a rerun does not erase them.

## Output
Return a consolidated report prioritizing:
1. Blockers (critical issues with demonstrated impact).
2. Material improvements.
3. Untested areas or hypotheses.

## Limitations
- This procedure does not prove whole-repository safety from a diff.
- Parallel review adds cost and may duplicate blind spots.
- No compliance validation or automated quality scoring is performed.
