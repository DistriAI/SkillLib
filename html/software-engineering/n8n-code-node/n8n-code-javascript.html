# JavaScript Code Node

## When to Use Code Node
Use Code node when:
- Complex transformations requiring multiple steps
- Custom calculations or business logic
- Recursive operations
- API response parsing with complex structure
- Multi-step conditionals
- Data aggregation across items

Consider other nodes when:
- Simple field mapping → Use Set node
- Basic filtering → Use Filter node
- Simple conditionals → Use IF or Switch node
- HTTP requests only → Use HTTP Request node

## Essential Rules
1. Choose "Run Once for All Items" mode (recommended for most use cases).
2. Access data: $input.all(), $input.first(), or $input.item.
3. Return [{json: {...}}] — the canonical, mode-portable form.
4. CRITICAL: Webhook data is under $json.body (not $json directly).
5. Built-ins available: this.helpers.httpRequest() (no auth), DateTime (Luxon), $jmespath().
   - Note: The bare $helpers global is undefined in the task-runner sandbox.
   - Not available: this.helpers.httpRequestWithAuthentication, $env (when blocked), require() (unless allowlisted).
6. For anything beyond a trivial unauthenticated GET, prefer the HTTP Request node.

## Mode Selection Guide
### Run Once for All Items (Recommended)
- Use for: Aggregation, filtering, batch processing, transformations.
- Data access: $input.all()
- Performance: Faster for multiple items (single execution).

### Run Once for Each Item
- Use for: Item-specific logic, independent operations, per-item validation.
- Data access: $input.item
- Performance: Slower for large datasets (multiple executions).
