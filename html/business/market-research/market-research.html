# Market Research

This skill supports three distinct modes. Select the mode based on the user's request and the tools available in the environment.

## Mode Selection

- **Founder Workflow (local file):** Use when the user is a founder iterating on a startup idea and the environment has a `startup/` directory with `core.md`. The goal is to maintain a living `startup/market-research.md` file.
- **API Lookup (Gooseworks):** Use when the user needs specific company lists, financials, or decision-maker contacts and the environment has `~/.gooseworks/credentials.json`.
- **Structured Report (econstack):** Use when the user wants a formal, source-cited market analysis report with fixed frameworks (Porter's Five Forces, PESTLE, HHI/CR4) and the environment has the econstack CLI tools installed.

## Mode 1: Founder Workflow (Local File)

### Before you start
1. Read `startup/core.md` to load project context (name, seed description, B2B or B2C, and all fields under `## Core`).
2. Check if `startup/market-research.md` exists.

### When market research already exists
Load the file for context. Infer intent from the conversation:
- **Asking about a specific dimension** (size, segments, pricing, trends): answer from the existing file; if thin, offer targeted research.
- **Wanting to update a section:** read the file, discuss new information, propose the change, get confirmation, write it back. Update `last_updated` in frontmatter.
- **Flagging research as stale:** set `status: needs-refresh` in frontmatter and offer to re-run full or targeted research.
- **Wanting web research on a specific topic:** dispatch the `web-researcher` agent with a focused prompt; incorporate findings into the relevant section; save full output to `startup/research/{YYYY-MM-DD}-{topic-slug}-research.md` with frontmatter `date`, `topic`, and `source_skill: market-research`.
- **Asking how research connects to hypotheses:** surface which findings could confirm or challenge existing hypotheses.

File format conventions:
- YAML frontmatter: `version` (number), `last_updated` (ISO date), `type` (`b2b` or `b2c`), `status` (`draft`, `complete`, or `needs-refresh`)
- H1 heading: `Market Research — {Project Name}`
- Sections: Market Overview, Customer Segments, Buying Behavior, Pricing Landscape, Trends, Key Sources, Open Questions

Read before writing, propose before saving, get confirmation.

### When no market research exists
Load the reference file for the guided first-time workflow:
```
.claude/skills/market-research/references/initial-market-research.md
```

### Ad-hoc web search vs. dispatching web-researcher
- **Inline WebSearch / WebFetch:** single-fact lookups, quick verification, one data point in flow. Stays in conversation, no persistence.
- **Dispatch web-researcher:** multi-source passes, structured landscape passes. Output is structured and saved to `startup/research/{YYYY-MM-DD}-{topic-slug}-research.md`.

Rough rule: one fact in flow → inline. Multi-source or results-should-persist → dispatch.

## Mode 2: API Lookup (Gooseworks)

### Setup
Read credentials from `~/.gooseworks/credentials.json`:
```bash
export GOOSEWORKS_API_KEY=$(python3 -c "import json;print(json.load(open('$HOME/.gooseworks/credentials.json'))['api_key'])")
export GOOSEWORKS_API_BASE=$(python3 -c "import json;print(json.load(open('$HOME/.gooseworks/credentials.json')).get('api_base','https://api.gooseworks.ai'))")
```
If the file does not exist, tell the user to run: `npx gooseworks login`.
All endpoints use Bearer auth: `-H "Authorization: Bearer $GOOSEWORKS_API_KEY"`.

### Step 1: Identify Key Players
```bash
curl -s -X POST $GOOSEWORKS_API_BASE/v1/proxy/orthogonal/run \
  -H "Authorization: Bearer $GOOSEWORKS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"api":"fiber","path":"/v1/natural-language-search/companies","query":"<query>"}'
```

### Step 2: Research Company Details
```bash
curl -s -X POST $GOOSEWORKS_API_BASE/v1/proxy/orthogonal/run \
  -H "Authorization: Bearer $GOOSEWORKS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"api":"fiber","path":"/v1/company-search","searchParams":{"company_names":["<names>"],"include_financials":true}}'
```

### Step 3: Find Decision Makers
Use Apollo first ($0.01 flat per call):
```bash
curl -s -X POST $GOOSEWORKS_API_BASE/v1/proxy/apollo/mixed_people/search \
  -H "Authorization: Bearer $GOOSEWORKS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"person_titles":["CEO","CTO","VP Product","Head of Sales"],"organization_domains":["<domains>"],"per_page":25}'
```
Fallback — Fiber people search ($0.02/record):
```bash
curl -s -X POST $GOOSEWORKS_API_BASE/v1/proxy/fiber/v1/people-search \
  -H "Authorization: Bearer $GOOSEWORKS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"searchParams":{"company_names":["<names>"],"job_titles":["CEO","CTO","VP Product","Head of Sales"]}}'
```

### Tips
- Cite specific sources and dates for statistics.
- Compare multiple analyst reports.
- Look for both bullish and bearish perspectives.
- Update research quarterly for fast-moving markets.

## Mode 3: Structured Report (econstack)

### Preamble
Before starting, run silently:
```bash
~/.claude/skills/econstack/bin/econstack-update-check 2>/dev/null || true
```
If it outputs UPDATE_AVAILABLE, tell the user: "A new version of econstack is available. Run `cd ~/.claude/skills/econstack && git pull` to update." Then continue.

Load prior learnings:
```bash
eval "$(~/.claude/skills/econstack/bin/econstack-slug)"
~/.claude/skills/econstack/bin/econstack-learnings-read --limit 3 2>/dev/null || true
```
If learnings are found, apply them. When a prior learning influences a decision, note: "Prior learning applied: [key]".

Check parameter database:
```bash
PARAMS_DIR="$HOME/econstack-data/parameters"
if [ -d "$PARAMS_DIR" ]; then
  PARAM_COUNT=$(find "$PARAMS_DIR" -name "*.json" 2>/dev/null | wc -l | tr -d ' ')
  echo "PARAMS: $PARAM_COUNT files loaded from $PARAMS_DIR"
  STALE=$(find "$PARAMS_DIR" -name "*.json" -mtime +730 2>/dev/null | wc -l | tr -d ' ')
  if [ "$STALE" -gt 0 ]; then
    echo "PARAMS_WARNING: $STALE file(s) not updated in 2+ years. Run: cd ~/econstack-data && git pull"
  fi
else
  echo "PARAMS: not found. Using built-in defaults."
fi
```

### Safety Rules
1. Parameter database is read-only. Never write to, modify, or delete files in `~/econstack-data/parameters/`.
2. Confirm before overwriting. Before writing an output file, check if a file with the same name already exists. If it does, ask the user: "A file named [filename] already exists. Overwrite it, or save with a new name?"

### Arguments
```
/market-research [sector or product] [options]
```
Options:
- `--geo <code(s)>`: `uk` (default), `us`, `eu`, `au`, or `global`. Multi-geography via commas.
- `--depth <level>`: `quick`, `standard` (default), `deep`.
- `--focus <topic>`: `sizing`, `competition`, `regulation`, `supply-chain`, `pricing`, `outlook`.
- `--section <name>`: `full` (default), `summary`, `sizing`, `players`, `concentration`, `porter`, `pestle`, `regulation`, `supply`, `trade`, `pricing`, `outlook`.
- `--format <type>`: `markdown` (default), `xlsx`, `word`, `pptx`, `pdf`, or `all`.
- `--client "Name"`: Add "Prepared for" metadata.

### Report Structure
Produce a structured, source-cited report covering: market sizing, key players, concentration (HHI/CR4), Porter's Five Forces, PESTLE macro-environment, regulatory environment, supply chains, trade flows, pricing, and outlook. Every data point is cited.

### Completion Status
At the end of every run, report one of:
- **DONE**: Analysis complete, output generated, all sections finished.
- **DONE_WITH_CONCERNS**: Output generated but with caveats.
- **BLOCKED**: Cannot proceed.
- **NEEDS_CONTEXT**: Need more information from the user.

Format: `STATUS: [status] | [one-line reason]`

### Capturing New Learnings
After completing the skill, log new insights via:
```bash
~/.claude/skills/econstack/bin/econstack-learnings-log '{"skill":"...","type":"...","key":"...","insight":"...","confidence":N,"source":"observed|user-stated|inferred"}'
```
Types: `framework`, `parameter`, `data-source`, `output`, `operational`, `preference`. Confidence: 9-10 observed/stated, 6-8 strong inference, 4-5 weak.

## Conflicts
- **davepoon/buildwithclaude vs gooseworks-ai/goose-skills:** davepoon uses local file state and inline WebSearch/WebFetch or a web-researcher subagent, while gooseworks requires external API credentials and makes authenticated curl calls to Orthogonal/Fiber/Apollo endpoints.
- **davepoon/buildwithclaude vs brycewang-stanford/Auto-Empirical-Research-Skills:** davepoon is a conversational, intent-inferred workflow with no fixed report structure, while brycewang enforces a fixed report structure, CLI preambles, parameter database checks, and completion status reporting.
- **gooseworks-ai/goose-skills vs brycewang-stanford/Auto-Empirical-Research-Skills:** gooseworks sources data via external paid APIs with per-call costs, while brycewang uses local CLI tools, a local parameter database, and WebSearch/WebFetch with no external API credentials.
