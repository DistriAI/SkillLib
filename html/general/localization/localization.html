# Localization

Use this skill when the user asks to add languages, translate UI text, or set up multilingual support. First identify the target surface: Unity app, web/product site, or App Store listing. Then follow the matching section below.

## 1. Unity Localization

1. Verify the `com.unity.localization` package is installed by reading `Packages/packages-lock.json`. If missing, install it with `UnityEditor.PackageManager.Client.Add("com.unity.localization")` and poll the lock file in a later call until the id appears.
2. Confirm the `Unity.Localization` assemblies are loaded before using Localization APIs.
3. Find or create `LocalizationSettings` under `Assets/Localization/LocalizationSettings.asset`, assign it to `LocalizationEditorSettings.ActiveLocalizationSettings`, and ensure required locales exist.
4. When populating String or Asset tables, match locales by `Locale.Identifier.Code` explicitly. For Asset Tables, use the asset GUID as the shared id.
5. After modifying tables, call `EditorUtility.SetDirty` on the collection and shared data, raise the Unity 6+ collection-modified event, and call `AssetDatabase.SaveAssets()`.
6. For UI, use fully qualified `UnityEngine.UI` types, avoid duplicate canvas instances, and use the Localization Scene Controls window for editor preview. For runtime switching, set `LocalizationSettings.SelectedLocale` and configure a startup locale selector on the settings asset. Do not hand-roll locale state.

## 2. Web/Product Localization Strategy

1. Establish the current state from the production site, route/CMS inventory, navigation, sitemap, source repository, analytics, and search data. A sitemap alone is not a complete page inventory.
2. Decide whether a locale should launch by separating language support, locale support, and market entry. Do not create country-specific copies without a maintained user or market distinction.
3. Define a coverage model with states such as `source-current`, `translation-draft`, `localized-ready`, `outdated`, and `not-applicable`. Apply stricter release gates to core product, pricing, checkout, legal, and high-intent pages.
4. Choose a stable, crawlable URL architecture. Ensure the URL, rendered language, `<html lang>`, navigation, metadata, and structured data describe the same locale. Keep canonical, hreflang, sitemap, internal links, and redirects consistent.
5. Coordinate content production by locking the source version, using target-market keyword research, producing translated copy with glossary and style review, and adapting examples, pricing, dates, units, imagery, and compliance only when verified.
6. Migrate existing locale URLs by capturing the current inventory, freezing the target URL policy, mapping old URLs to equivalent new locale URLs, and adding permanent redirects where needed.

## 3. App Store Listing Localization

1. Read `app-marketing-context.md` if present, ask for the App ID, and determine whether the app itself is localized or only the store listing.
2. Prioritize markets using market size, competition, effort, revenue potential, and strategic fit. Use the provided Tier 1 and Tier 2 market lists as a starting point.
3. Localize metadata per market: title, subtitle, keyword field, description, promotional text, What's New, screenshots, and app preview video.
4. Do not translate English keywords directly. Run keyword research for each target market separately and use local search terms and competitor metadata.
5. Apply cultural adaptation to screenshots, colors, imagery, tone, features, social proof, and pricing.
6. Launch and monitor keyword rankings and conversion rates by country, then iterate based on performance data.

## Conflicts

- kostja94/marketing-skills treats localization as web/product URL, hreflang, and coverage strategy.
