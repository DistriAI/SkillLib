# Briefing Note Skill

Generate a concise, decision-focused briefing note. The output should be scannable in 2 minutes and fit within 1-2 pages.

## 1. Determine Mode and Inputs

Ask the user for the following if not provided:
- **Topic/Issue**: What is the note about?
- **Audience**: Who is it for? (e.g., Minister, Board, Executive, Public)
- **Purpose**: Decision, Information, or Meeting prep?
- **Mode**:
  - **General**: A simple, one-page executive summary.
  - **Policy/Gov**: A structured note using a specific template (e.g., UK GES, AU Treasury).

## 2. Data Integration (Optional)

If the user requests data or if `econstack` tools are available and relevant:
- Run `~/.claude/skills/econstack/bin/econstack-update-check` silently.
- Use `--data` flag logic to pull relevant statistics (ONS, BoE, FRED) if applicable.
- *Note: If econstack is not installed, skip this step and rely on user-provided facts or general knowledge.*

## 3. Drafting Structure

### Mode A: General Executive Brief (1 Page)
Use this structure for quick, high-level updates:

**BRIEFING NOTE — [Subject]**
**Date · Prepared for · Purpose:** [Decision / Info / Meeting]

**Issue**
- 1-2 lines: What is this about and why now?

**Background**
- Minimum context needed (dates, key players, current status).
- No history for its own sake.

**Key Considerations**
- Bullets: Facts, risks, sensitivities (financial, legal, political), stakeholder positions.

**Recommendation / Decision Sought**
- Clear action or decision needed.
- If for info: Key messages and likely questions.

**Contact**
- Who to follow up with.

### Mode B: Policy/Government Brief (1-2 Pages)
Use this structure for detailed policy analysis (default: UK GES style):

**[Classification: e.g., RESTRICTED / OFFICIAL-SENSITIVE]**
**TO:** [Audience]
**FROM:** [Author/Team]
**DATE:** [Date]
**SUBJECT:** [One-line topic]

**1. ISSUE**
- 1-2 sentences: What decision is needed and why now?

**2. BACKGROUND**
- 3-5 sentences: Context, current position, why it matters.

**3. ANALYSIS**
- Core analysis with 1-3 key findings.
- Each finding: Bolded topic sentence + 1-2 sentences of evidence/citation.

**4. OPTIONS**
- 2-4 options. For each:
  - What it involves (1 sentence)
  - Cost/Benefit (1 line)
  - Pros (1-2 bullets)
  - Cons (1-2 bullets)

**5. RECOMMENDATION**
- 1-2 sentences: Which option and why.
- If neutral stance: Present trade-offs and leave decision to reader.

## 4. Quality Checks

- [ ] **Conciseness**: Fits on 1 page (General) or 1-2 pages (Policy). Scannable in ~2 minutes.
- [ ] **Clarity**: Purpose is stated up front.
- [ ] **Balance**: No editorializing; flag where judgment is involved.
- [ ] **Risks**: Key sensitivities/risks are surfaced, not buried.
- [ ] **Action**: Ends with a clear recommendation or specific decision sought.

## 5. Anti-Patterns

- Do not write an essay; use bullets and tight prose.
- Do not include unnecessary history; annex it if needed.
- Do not bury the ask; state the decision sought plainly.
- Do not omit risks; surprising the principal is the cardinal sin.

## 6. Output

- Default to Markdown.
- If `--format-output` is specified (e.g., word, pdf), generate in that format if tools are available.
- Report status: `STATUS: DONE | [one-line reason]`
